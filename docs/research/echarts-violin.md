# The box plot's violin: `@echarts-x/custom-violin` 1.1.1, and ECharts 6.1.0's custom series

Researched for T992 (AC-592; design 23 sheet 11; 23-Q10 (a): "research the violin package before import, and draw with wechart's own custom series if a package is unmaintained"). By lane CHARTS-B's integration-researcher, 2026-10-18.

## Conclusion

**Don't import the package. Draw the violin with wechart's own `type: 'custom'` series (`CustomChart`, already in `echarts/charts`).** `packages: []`: the fallback uses only `echarts/charts` and `echarts/core`, which `docs/research/echarts.md` covers.

- **Correctness:** the package evaluates its density only on 0 to 10 data units, with a bandwidth fixed at 1 data unit, so real measures are drawn wrong or not at all. A maintainer confirmed it in [#12](https://github.com/apache/echarts-custom-series/issues/12) (open since 2025-11-07); [#21](https://github.com/apache/echarts-custom-series/issues/21) (negative values, open since 2026-02-16) has a proposed patch and no response.
- **Fit:** it can't draw AC-592's 1.5 px edge (its polygon style is `fill` and `opacity` only), its group is `silent: true` so AC-593's marking can't work, and its KDE lives in the renderer, out of reach of the text alternative ([violin.esm.mjs](https://unpkg.com/@echarts-x/custom-violin@1.1.1/dist/violin.esm.mjs)).
- **Maintenance:** the violin source's last change is 2025-08-12; since 1.1.1 (2026-01-12) only Dependabot merges; no per-package tags; 143 downloads a week ([folder history](https://github.com/apache/echarts-custom-series/commits/main/custom-series/violin), [registry](https://registry.npmjs.org/@echarts-x/custom-violin)). Unmaintained for 23-Q10 (a)'s purpose.

## The package, for the record

- `latest` 1.1.1, Apache-2.0, peer `echarts ^6.0.0`, no runtime dependencies; ESM, CJS and an auto-registering browser build; types for the default export only ([package.json](https://unpkg.com/@echarts-x/custom-violin@1.1.1/package.json), [violin.d.ts](https://unpkg.com/@echarts-x/custom-violin@1.1.1/dist/violin.d.ts)).
- Registered through `echarts.use(violin)`, whose `install` calls `registerCustomSeries('violin', renderItem)` ([extension.ts](https://raw.githubusercontent.com/apache/echarts/6.1.0/src/extension.ts), [customSeriesRegister.ts](https://raw.githubusercontent.com/apache/echarts/6.1.0/src/chart/custom/customSeriesRegister.ts)). In 6.1.0's typings `renderItem` is a function type only, so a string `renderItem` needs a cast under strict TS ([custom.md](https://raw.githubusercontent.com/apache/echarts-doc/master/en/option/series/custom.md)).
- Its KDE: Epanechnikov kernel `|u| <= 1 ? 0.75(1 − u²) : 0`, `sum K((x − xi)/h) / (n h)`, `h = 1`, evaluated at `i · 10/(binCount − 1)`; `bandWidthScale` only widens the drawing ([src/index.ts](https://raw.githubusercontent.com/apache/echarts-custom-series/main/custom-series/violin/src/index.ts)).

## ECharts 6.1.0's custom series: what wechart uses

- **Registration:** `CustomChart` is exported from `echarts/charts`, with `CustomSeriesOption` ([charts.ts lines 43, 69](https://raw.githubusercontent.com/apache/echarts/6.1.0/src/export/charts.ts)). It must be added to the `echarts.use([...])` lists in `packages/charts/src/echarts.ts` and `packages/charts/src/testing/renderToSvg.ts`, which don't register it today.
- **Option:** `{ type: 'custom', coordinateSystem: 'cartesian2d' (default), renderItem, encode, clip (default false), z (default 2) }`; `itemStyle`, `label` and `emphasis` are deprecated ([CustomSeries.ts](https://raw.githubusercontent.com/apache/echarts/6.1.0/src/chart/custom/CustomSeries.ts)).
- **`renderItem(params, api)`:**
  - `params`: `context`, `dataIndex`, `dataIndexInside`, `seriesIndex`, `coordSys` (`{ type: 'cartesian2d', x, y, width, height }`), `encode`, `itemPayload`.
  - `api.value(dim, i?)` (on a category dimension, the ordinal index); `api.coord([x, y])` (`dataToPoint`); `api.size?(dataSize)`, which on a **category** axis returns the band width whatever is passed ([prepareCustom.ts](https://raw.githubusercontent.com/apache/echarts/6.1.0/src/coord/cartesian/prepareCustom.ts)).
  - Returns graphic elements: `polygon` (`shape.points`), `path`, `group` (`children`), with `style: { fill, fillOpacity, stroke, lineWidth, opacity }` ([custom.md](https://raw.githubusercontent.com/apache/echarts-doc/master/en/option/series/custom.md)). Returning null removes the item's element ([CustomView.ts](https://raw.githubusercontent.com/apache/echarts/6.1.0/src/chart/custom/CustomView.ts)).
- **`encode`:** "In most cases, series.encode needs to be specified when using custom series … then echarts can render appropriate axis by the extent of those data" ([custom.md](https://raw.githubusercontent.com/apache/echarts-doc/master/en/option/series/custom.md)). A violin item can carry `[category, low, high]` with `encode: { x: 0, y: [1, 2] }`, or wechart sets the axis's ends itself (as T991-1 does).
- **In SSR SVG:** with animation off and no `smooth`, a `polygon` is written as `<polygon points="x y x y …">`, otherwise as `<path d>` ([graphic.ts](https://raw.githubusercontent.com/ecomfe/zrender/6.1.0/src/svg/graphic.ts)). `fill-opacity` is `fillOpacity × alpha × opacity`, written only below 1; `stroke-width` is written only when a stroke is set and is not 1; a path or polygon never gets an `opacity` attribute ([mapStyleToAttrs.ts](https://raw.githubusercontent.com/ecomfe/zrender/6.1.0/src/svg/mapStyleToAttrs.ts)). So `fillOpacity: 0.24, lineWidth: 1.5` draws `fill-opacity="0.24" stroke-width="1.5"`. Each element is stamped `ecmeta_series_index`, `ecmeta_data_index` and `ecmeta_ssr_type="chart"` ([graphic.ts](https://raw.githubusercontent.com/ecomfe/zrender/6.1.0/src/svg/graphic.ts), [CustomView.ts](https://raw.githubusercontent.com/apache/echarts/6.1.0/src/chart/custom/CustomView.ts)).

## Gotchas

1. **Z-order:** custom and boxplot both default to `z: 2`; zrender sorts by `zlevel`, `z`, `z2` stably, so give the violin a lower `z` (1) rather than relying on series order ([CustomSeries.ts](https://raw.githubusercontent.com/apache/echarts/6.1.0/src/chart/custom/CustomSeries.ts), [Storage.ts](https://raw.githubusercontent.com/ecomfe/zrender/6.1.0/src/Storage.ts)).
2. **The box's width:** boxplot's `boxWidth` defaults to `[7, 50]`; AC-592's 20 px box is `boxWidth: [20, 20]` ([BoxplotSeries.ts](https://raw.githubusercontent.com/apache/echarts/6.1.0/src/chart/boxplot/BoxplotSeries.ts)). For one boxplot series ECharts makes the box `min(max(0.8 · band − 2, lower), upper)` wide, the bounds read from `boxWidth` (pixels or a percent of the band) (`calculateBase`, `echarts/lib/chart/boxplot/boxplotLayout.js` lines 71–100 of the installed 6.1.0; added by lane CHARTS-B, 2026-10-18). So `[20, 20]` draws 20 px even on a band narrower than that, over its neighbours; `[0, 20]` draws 20 px where the band allows and `0.8 · band − 2` below it.
3. **Clip:** custom series don't clip by default, so a violin's tails past the axis ends would draw over the labels; set `clip: true` or keep the tails inside the axis ends ([CustomSeries.ts](https://raw.githubusercontent.com/apache/echarts/6.1.0/src/chart/custom/CustomSeries.ts)).
4. **Animation and `smooth`:** either makes a polygon a `<path d>` in SVG ([graphic.ts](https://raw.githubusercontent.com/ecomfe/zrender/6.1.0/src/svg/graphic.ts)). `renderToSvg` forces animation off.
5. **Test readers:** wechart's SVG readers match `<path>`; a violin is a `<polygon points>`.
6. UNVERIFIED: a boxplot and a custom series drawn together (no official example; both are `cartesian2d`); ECharts 6.0.0's `tooltipDisabled` for custom series (placement not checked).

## Kernel density references

Silverman's rule of thumb is `h = 0.9 · min(σ̂, IQR/1.34) · n^(-1/5)`; the Gaussian-reference form is `≈ 1.06 σ̂ n^(-1/5)`, which "can yield widely inaccurate estimates when the density is not close to being normal" ([Wikipedia: KDE](https://en.wikipedia.org/wiki/Kernel_density_estimation)). Vega's `bandwidth.js` (vega-statistics) uses `1.06 · min(σ, IQR/1.34) · n^-0.2`, with fallbacks, citing Scott (1992) ([vega bandwidth.js](https://raw.githubusercontent.com/vega/vega/main/packages/vega-statistics/src/bandwidth.js)).

Not decided by the spec (left to the implementer's recorded decision or the user): the kernel and bandwidth rule; how violins are scaled across categories; where the tails end; the edge's colour; a category with one value or all values equal.
