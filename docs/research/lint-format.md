# Lint/format tooling: Biome 2.5.14 vs ESLint 10.11.0 + typescript-eslint 8.70.0 + Prettier 3.9.8

## Summary

Decision input for wechart's quality hook, which runs formatter+linter then a typecheck on every edit, and must support AC-176 (keyboard reachability + visible focus indicator) and AC-177 (icon+text pairing for status). Compared Biome (single Rust binary: linter+formatter+import sorter) against ESLint+typescript-eslint (rules) + Prettier (formatting). All version numbers pulled live from npm registry `latest` on 2026-09-19.

## Rule coverage

**React hooks correctness.** Biome ships `useExhaustiveDependencies` (equivalent to `react-hooks/exhaustive-deps`) and `useHookAtTopLevel` ("Same as react-hooks/rules-of-hooks", both `recommended`/error). [use-exhaustive-dependencies](https://biomejs.dev/linter/rules/use-exhaustive-dependencies/), [use-hook-at-top-level](https://biomejs.dev/linter/rules/use-hook-at-top-level/). eslint-plugin-react-hooks 7.x is a rewrite: `recommended-latest` now enables the React Compiler's diagnostic rules by default (e.g. `set-state-in-effect`, ref/immutability checks) in addition to the two classic rules — a broader correctness surface than Biome's two rules. [react-hooks CHANGELOG](https://github.com/facebook/react/blob/main/packages/eslint-plugin-react-hooks/CHANGELOG.md)

**JSX accessibility.** Biome has 37 built-in a11y rules, essentially a 1:1 port of jsx-a11y (`no_access_key`→`no-access-key`, `use_key_with_click_events`→`click-events-have-key-events`, etc.), and is still adding rules (`useControlLabel` added in 2.5.12, `useAnchorContent` fixed in 2.5.14). [Biome a11y rule source](https://github.com/biomejs/biome/tree/main/crates/biome_js_analyze/src/lint/a11y), [CHANGELOG](https://raw.githubusercontent.com/biomejs/biome/main/packages/%40biomejs/biome/CHANGELOG.md). eslint-plugin-jsx-a11y 6.10.2 has 39 rules. [jsx-a11y rules](https://github.com/jsx-eslint/eslint-plugin-jsx-a11y#supported-rules). Coverage is near-parity for AC-176-relevant rules (`noNoninteractiveTabindex`/`no-noninteractive-tabindex`, `noPositiveTabindex`/`tabindex-no-positive`, `useKeyWithClickEvents`/`click-events-have-key-events`, `useFocusableInteractive`/`interactive-supports-focus`, `useButtonType`, `useValidAnchor`). **Neither tool lints for a visible `:focus` indicator or for icon+text pairing** (AC-177) — both are CSS/design-pattern concerns outside a JS/JSX AST linter's scope; this is a gap for both candidates, not a differentiator.

**Type-aware rules.** typescript-eslint's `recommendedTypeChecked`/`strictTypeChecked` presets are mature, stable rule sets (`no-floating-promises`, `no-misused-promises`, `no-unsafe-assignment`, `no-unnecessary-condition`, `restrict-template-expressions`, etc.), backed by the real `tsc` type checker via `parserOptions.projectService`. [typed linting](https://typescript-eslint.io/getting-started/typed-linting/). Biome v2 added an opt-in "types domain" with its own lightweight type-inference engine (not `tsc`); its flagship rule `noFloatingPromises` is explicitly documented as **nursery**: "experimental and the behavior can change at any time." [no-floating-promises](https://biomejs.dev/linter/rules/no-floating-promises/), [domains](https://biomejs.dev/linter/domains/). Biome's "project domain" (`noUnresolvedImports`, `noImportCycles`, `noPrivateImports`, `noUndeclaredDependencies`) does module-graph resolution but explicitly _without_ type inference. [domains](https://biomejs.dev/linter/domains/)

**Import ordering.** Biome's `organizeImports` assist action is built in: groups by `:URL:`/`:NODE:`/`:PACKAGE:`/`:ALIAS:`/`:PATH:`, natural sort, blank-line separators, configurable via `assist.actions.source.organizeImports`. [organize-imports](https://biomejs.dev/assist/actions/organize-imports/). The ESLint package list the caller gave (`eslint`, `@eslint/js`, `typescript-eslint`, `eslint-plugin-react-hooks`, `eslint-plugin-jsx-a11y`) **includes no import-order plugin** (e.g. `eslint-plugin-import`/`simple-import-sort`); as scoped, the ESLint candidate has zero import-ordering capability out of the box.

## Speed / per-file hook behaviour

Biome's default (`recommended`) rules are purely file-local AST analysis — fast, and match the hook's "one command, one file" model (`biome check --write <file>` formats + lints + organizes imports in one pass). Enabling a "project domain" rule (e.g. `noUnresolvedImports`) activates Biome's Scanner, which crawls the whole project to build a module graph even when only one file is targeted; Biome's own benchmark: ~2s for 2k files with the Scanner vs ~800ms without. [linter overview](https://biomejs.dev/linter/) These rules are not in the base `recommended` set, so a default config avoids this cost. [domains](https://biomejs.dev/linter/domains/)

typescript-eslint's type-aware rules require building the full TS program from `tsconfig.json` even for a single-file CLI invocation: "This requires TypeScript to analyze your entire project instead of just the file being linted," and the docs' own performance guidance assumes a long-lived IDE/editor process with caching — a fresh `eslint --fix <file>` process on every save gets none of that caching and re-parses the project each time. [typed linting](https://typescript-eslint.io/getting-started/typed-linting/) This duplicates the hook's separate typecheck step. In both tools, diagnostics from a partial/single-file run are still scoped to that file — neither reports problems located in _other_ files; type-aware ESLint only lets the linted file's own diagnostics benefit from cross-file type information (e.g. a call to a wrongly-typed function defined elsewhere still surfaces as an error in the file that calls it).

## Monorepo configuration and ignoring `.claude/`

Biome v2 has native hierarchical monorepo support: a root `biome.json`, nested `biome.json` files with `"root": false` and `"extends": "//"` to inherit root settings, run from repo root or any package. To ignore `.claude/` everywhere: `{"files": {"includes": ["**", "!!.claude/**"]}}` (force-ignore, `!!` prefix), or set `vcs.useIgnoreFile: true` to also honor `.gitignore`. [big-projects guide](https://biomejs.dev/guides/big-projects/), [configuration reference](https://biomejs.dev/reference/configuration/)

ESLint flat config has no built-in workspace concept; a single root `eslint.config.js` with per-glob config objects covers a pnpm workspace. Ignore `.claude/` via `globalIgnores(['.claude/'])` (or `**/.claude/` for nested occurrences). [ESLint ignore docs](https://eslint.org/docs/latest/use/configure/ignore) Prettier needs a `.prettierignore` entry (`.claude/`) — it has no workspace-aware config of its own.

## Formatter differences in a dense codebase

Current pinned defaults mostly **match**, closing gaps that existed in older versions: both default `printWidth`/line width `80`, `trailingComma: "all"` (Prettier changed its default from `es5` to `all` in v3 [Prettier options](https://prettier.io/docs/options.html); Biome's default is also `all` [Biome formatter](https://biomejs.dev/formatter/)), `arrowParens: "always"`, `semi: true`/always, double quotes in JSX. One real default mismatch: **Biome's default `indentStyle` is `tab`**, not spaces — must be set to `"space"` explicitly to match the conventional JS ecosystem style Prettier defaults to (`useTabs: false`). [Biome formatter defaults](https://biomejs.dev/formatter/) Remaining differences are documented edge cases, not everyday-visible: object computed-key parenthesization, a trailing comma Prettier adds after defaulted generic type params that Biome omits, and non-null-assertion parens on optional chains. Biome's parser is also stricter and prints certain invalid-but-Prettier-tolerated syntax verbatim as "bogus nodes" instead of formatting it. [differences with Prettier](https://biomejs.dev/formatter/differences-with-prettier/)

**Coverage gap that matters for this repo:** Biome's formatter support for **Markdown and YAML is listed "In progress" (not stable)**; CSS and JSON/JSONC are fully supported. [language support](https://biomejs.dev/internals/language-support/) wechart's repo is Markdown-heavy (`docs/requirements.md`, `docs/spec.md`, `docs/research/*.md`, `docs/tasks.md`) and has YAML (`docker-compose.yml`). Adopting Biome would not eliminate Prettier for this repo today — Prettier (or another formatter) would still be needed for `.md`/`.yml` files, making a "Biome-only" setup a hybrid in practice, not a clean replacement.

## Recommendation

**ESLint 10.11.0 + typescript-eslint 8.70.0 + eslint-plugin-react-hooks 7.1.1 + eslint-plugin-jsx-a11y 6.10.2 + Prettier 3.9.8**, on rule coverage and maturity grounds only:

1. **AC-176/AC-177 correctness backbone**: jsx-a11y (39 rules) and Biome's a11y set (37 rules) are near-equivalent for keyboard/focus-related checks, so accessibility rule coverage is not the deciding factor — but react-hooks 7.x's React-Compiler-derived rules (beyond exhaustive-deps/rules-of-hooks) give strictly more hook-correctness coverage than Biome's two hook rules, which matters for the interactive, state-heavy dashboard/chart-editor UI this app is building.
2. **Type-aware correctness**: typescript-eslint's type-checked rule sets are stable and run on real `tsc` output; Biome's equivalent is explicitly nursery/experimental on its own non-`tsc` inference engine. For strict-mode TypeScript correctness this is a material maturity gap, not a matter of taste.
3. **Format coverage**: Prettier formats the Markdown/YAML that make up a large share of this repo's own governed artifacts (`docs/*.md`, `docker-compose.yml`); Biome does not yet, stably. Choosing Biome would still require keeping Prettier around for those files, undermining the "one tool" premise.
4. Import ordering is Biome's one clear built-in advantage over the ESLint package list as scoped; this alone does not outweigh points 1–3 since ESLint's ecosystem has mature import-order plugins available (not in the caller's candidate list, but importable once a research doc covers them).

## Gotchas

- ESLint 10 dropped `FlatESLint`/`LegacyESLint` and the eslintrc format outright — `eslint.config.js` flat config only. [migration guide](https://eslint.org/docs/latest/use/migrate-to-10.0.0)
- typescript-eslint's `typescript-eslint` meta-package exports `configs`, `parser`, `plugin`, and a `config()` helper now superseded by ESLint's own `defineConfig`. [typescript-eslint package docs](https://typescript-eslint.io/packages/typescript-eslint/)
- Biome's `noUnusedImports` is `recommended` by default (warn) and has an _unsafe_ auto-fix that can delete comments attached to the removed import — worth checking hook output before trusting `--write`. [no-unused-imports](https://biomejs.dev/linter/rules/no-unused-imports/)

## Open questions / unverified

- Whether Biome's `noFloatingPromises`/types-domain rules will graduate out of nursery on a timeline relevant to this project — not stated in current docs.
- No linter (Biome or ESLint) enforces AC-176's "visible focus indicator" or AC-177's "icon + text label" pairing; these ACs will need a different verification mechanism (e.g. component tests or visual/a11y test tooling), regardless of which lint/format choice is made — flagging for `component-research` to cover separately, not resolved by this doc.
- If Biome is later reconsidered specifically for its speed/import-ordering advantages, its Markdown/YAML formatter status should be re-checked, since "In progress" may change.
