## API surface wechart will use

### Folder views' `sql_alias`, and the upgrade

- `generatedAlias` (`publish.ts` L123-146): a folder view gets `aliasOf(fullName)`, a root view none; cubes as at `0406293add`.
- `assignAliases` covers every item with no authored `sql_alias` (L158). A kept item whose alias differs is re-dumped and counted as changed (L162-172).
- The test uses a 33-character folder id and a view including a time dimension (`names.test.ts` L207-228).
- **At start nothing is re-aliased.** At each model's first publish on this image, every due kept item is re-dumped; the revision is new even for an empty changeset.

| Kept item, no authored alias | Due at the first publish? | SQL / rollups change? |
| --- | --- | --- |
| Folder cube on a folder's source, last published on `ed08180c37` | Yes | Yes |
| Same, last published on `e53cf2a8b8` | No | No |
| Root cube on a root source ≠ `default`, last published on `ed08180c37` | Yes | Yes |

| Folder view (`ed08180c37` / `e53cf2a8b8`) | No | No |

wechart's seed model holds no `extends:`, `data_source:` or `sql_alias:`, so nothing in it is due.

### `PUT …/snapshot` with items

- Applied as a changeset: deletes what it doesn't send; upserts what is new, changed (kind or authored YAML), in a folder not in the new tree, or bound to a dropped item; keeps the rest with their stored bindings (`runtime.ts` L3032-3073).
- Items in a dropped folder are refused `422 invalid_items`, kind `folder`.
- A stale base is `409 conflict`, unless the content is already in (a retry, `200`).
- The folder tree is still replaced. A folder sent without `allowedGroups` keeps its groups unless it moved, when they are deleted (`revisions.ts` L772-780); wechart sends snapshot folders as `{ id, parentId }` only.

### A query into a folder the groups don't reach

- `XcubeApiGateway.getNormalizedQueries` throws `CubejsHandlerError(403, 'Forbidden', "None of these groups reaches folder <folderId> (<cube>)")` for the first cube or view the gate doesn't admit, only while the model's `permissions.security` is on.
- The body is `{ error }` only in production (compose runs `CUBEJS_DEV_MODE: 'false'`).
- The folder is xcube's id (`f<32 hex>` or `froot`); wechart maps it back.

| Path | Answer for an unreached folder |
| --- | --- |
| `GET`/`POST /v1/load`, `/v1/subscribe` | **403** |
| `GET /v1/sql?query=<json>` | `200`, SQL with `1 = 0` |
| `POST /v1/sql` with an object | 403, by reading |
| `GET /v1/dry-run` | Cube's own path (UNVERIFIED) |
| `/v1/meta` | items left out |
| folder admits, the cube's own policy denies | Cube's refusal (500 hidden member) |

### Proposals, history and security contracts

- **Overlays** (`admin/routes.ts` L178-188; `runtime.ts` L1507-1547): upserts ≤ 2000, deletes ≤ 2000, connections ≤ 20; ≤ `XCUBE_MAX_OVERLAYS` (1000) live, a new id past it `409 too_many_overlays`; `XCUBE_MAX_ACTIVE_OVERLAYS` (50) compiled per instance, the least recently used recompiled on its next query; two items of one short name refused `422`; `expiresAt = now + min(ttlSeconds ?? 86400, 604800)`, a larger `ttlSeconds` clamped silently; a GET or a query never renews; a re-push of the same content renews and keeps the version, **unless it no longer applies, which is `422` and not renewed**; a gone overlay named in a token is `410 { error }` (no `code`), while `GET …/overlays/{id}` for it is `404 unknown_overlay`.
- **Changesets:** `baseRevision` is required; a stale base is `409 { error, code: "conflict", currentRevision, currentItemsHash }`; a failure while the model moved on is `409` for an apply, re-checked for a dry run.
- **A break:** `{ folderId: string | null, name: string | null, line?, column?, kind, message }`, `kind` one of `yaml | item | reference | alias | compile | folder`; no file field. YAML errors carry line and column; Cube compile errors don't, and are placed on an item only when Cube's text names its file or starts with `<name> cube|view`. `cubeMessage` is Cube's whole text.
- **The test route** takes a body only: `{ driver, authMethod, fields, sealed }`. There is no test by overlay or name.
- **A restore** is an upsert, bound nearest-first as of now.
- **User tokens** carrying only `groups` get the folder gate and then the model's policies; there is no super role in a user token.
- **Security on** needs schema ≥ 4 on every instance, else `409 older_instances`.

## Gotchas for wechart

1. **Preview as groups (T438) sees the 403 only on `/v1/load`.** Its generated-SQL view, by GET, gets `200` with `1 = 0`. Asked of xcube (`to-xcube/2026-09-27-2330-sql-dry-run-403.md`).
2. **The 403 passes through wechart's API** as `403 { error, source: 'cube' }`. `TileUnavailable` matches only "You requested hidden member"; `e2e/security/cube-groups.spec.ts` expects that for the root view while the gate is off.
3. **A whole send now keeps what is published** (AC-273). wechart's serialisation docblocks (`model/publish.ts` L235-242, `publish-serial.test.ts` L10-17) give the older rebinding as their reason.
4. **A whole send that moves a folder clears its groups**, since wechart sends folders without `allowedGroups`. This predates the range, and matters once security is on.
5. **Proposal overlays:** to keep a proposal past a day, send `ttlSeconds` (clamped to 604800) on each push; a re-push only renews while the proposal still applies.
6. **Rolling upgrade:** until every Cube pod runs the new image, an older pod handling a snapshot still re-resolves everything.
