# Decisions: new chart types, lane A (lane CHARTS-A)

Later decisions for P2.27's new chart types (F49–F55, design 23), in the table of [`decisions-2026-10-08.md`](./decisions-2026-10-08.md)'s "Later decisions", kept here so the parallel lanes don't conflict there.

| ID | Question | Decision | Why | Departs |
|---|---|---|---|---|
| R81-A1 the lane's calls on R81-2 and R81-3 (AC-631, AC-632) | What the answers leave unsaid: how a dimension's browser bin marks, what Metrics may hold, how a duration combines with "First to last", and Unit's default | **A dimension's browser bin marks and cross-filters as a range on the dimension, as a model bin does; Metrics takes a summed measure only, each bin summing its grouped values' measure. A duration is evaluated per bar (per row with One row, per member with "First to last" from its earliest start); Unit has no default, and no bars draw until the author chooses one; an empty duration is an open bar and a negative one a reversed row (AC-603).** Recorded under R81 in `requirements-log.md`. Lane CHARTS-A's call, overturnable. | A bin of the dimension's own values is exact on the dimension, so a value list would mark less precisely than the data allows; summing is the only way to combine grouped values that stays exact; the user's "with a chosen unit" names no default. | No |
| T934-1 R81's ids, and the 100 % cards (AC-559, AC-584) | Which of R81's fifteen are chart types, and what are the 100 % cards? | **Eleven new `ChartType`s: `waterfall`, `histogram`, `bubble`, `parallel`, `bullet`, `sankey`, `funnel`, `timeline`, `calendar`, `icicle`, `graphicalTable`. The KPI, the box plot and the Map stay `kpi`, `boxplot` and `map`. 100 % stacked bar and area are gallery cards (`stackedBar100`, `stackedArea100`) that pin `stackedBar` or `stackedArea` and pass `stack: 'percent'` to the editor; until T957 adds Customize › Stack, the editor pins the stacked type and ignores the stacking.** Lane CHARTS-A's call, overturnable. | 23-Q15 (a) draws the 100 % cards as presets ("switching Stack back to Sum is the same chart"); AC-594 makes Bubble a card with its own needs and greying, and AC-560 a top pick, so it has an id; existing saved KPIs, box plots and country maps keep their ids (AC-562, AC-622). | No |
| T934-2 a greyed card's highlighted well (AC-217) | Which well is highlighted, and for how long? | **The first well the type lacks, in its requirements' order (`missingFor`), for today's types too (a Line with no time highlights Time); the well keeps `data-highlight="true"`, an accent outline, until the chart's fields next change or another type is drawn (by the gallery, Auto or a quick pick; the editor keeps the type it was chosen for and compares it). A requirement may name a type's own well (`target`), which `Wells` hands to the type's own wells module.** Lane CHARTS-A's call, overturnable. | AC-217 says "the editor then highlighting the well it needs"; a highlight that outlived the next edit would point at a well already filled. | No |
| T934-3 the Map card's words before its layers (AC-559, AC-622) | The Map card takes design 23's description and needs now, while only the Regions layer on Countries exists until T973 … T978 | **Its name ("Map"), description ("Regions, points or density on vector boundaries") and needs ("Needs a region key or a location, and a measure") are design 23's from T934; its greying stays today's (a dimension of ISO-3 codes, the Countries set's region key), so its missing sentence reads "Map needs a dimension of ISO-3 country codes in Dimensions; add 1 more." until T973 widens it.** Lane CHARTS-A's call, overturnable. | AC-559 names the card in design 23's words; an ISO-3 dimension is a region key of today's one boundary set, so the needs are true of what draws today. | No |
| T934-4 "gauge" in search (AC-559) | How does a search for "gauge" find Bullet chart and KPI, when neither's text holds the word? | **Each card may carry search words beyond its name and description; KPI's and Bullet chart's include "gauge". No card is named or described as a gauge.** Lane CHARTS-A's call, overturnable. | Design 23 screen 1 pin 7 asks for the two cards on that search; their descriptions don't hold the word. | No |
| T934-5 R81's types in the walks over every type (AC-037, AC-178) | `chart-editor.spec.ts`'s "no chart type is left undrawn" and `table-view.spec.ts` walk `CHART_TYPES`, which now holds types not drawn yet | **`e2e/r81Awaiting.ts` names R81's types still waiting for their series (`AWAITING_SERIES`) and their table view (`AWAITING_TABLE_VIEW`); the walks leave those out, and each type's series task and table-view task takes its line out. `optionFor.test.ts` likewise counts R81's types apart from the DOM types.** Lane CHARTS-A's call, overturnable. | Each R81 type's drawing and table view is its own task with its own criteria; the walks keep covering every type built, and each type joins them on the day it is built. | No |
| T934-6 tests that used a Sankey as a type no build knows | `openChart.test.ts`, `exportFile.test.ts` and `chartTypeLabels.test.ts` took `sankey` as the example of an unknown type | **They take `gauge` instead, which no wechart has (R81, "No gauge").** Lane CHARTS-A's call. | A Sankey is now a known type, so the tests no longer tested what they say; a gauge keeps them testing it. | No |
