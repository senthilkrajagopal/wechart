# Decisions: the new chart types (lane CHARTS-B)

Later decisions for P2.27 (F49–F55, design 23), in the table of [`decisions-2026-10-08.md`](./decisions-2026-10-08.md)'s "Later decisions", kept here so the parallel lanes don't conflict there.

| ID | Question | Decision | Why | Departs |
|---|---|---|---|---|
| T990-1 where Distribution is stored (AC-591, AC-306) | Under which option do Points and Violin live? | **`options.distribution: { points, violin }`, sparse: Outliers and no Violin are stored as nothing, so a box plot saved before R81, and one put back to the defaults, has no `distribution`. Anything unknown reads as the default.** Not flat `points`/`violin` keys, which other types (the Map's Points layer) may want. Lane CHARTS-B's call, overturnable. | Matches the Customize tab's sparse options (AC-219) and the section's name; AC-306's "Outliers draws as before R81" holds by construction. | No |
| T990-2 Outliers without Each point is (AC-591) | Design 23 sheet 11's "Unavailable" mock shows None chosen and Outliers greyed with no Each point is; AC-591 disables only All, Beeswarm and Violin. Which holds? | **AC-591: None and Outliers stay choosable without Each point is, and Outliers stays the default.** Lane CHARTS-B's call, overturnable. | A box plot without Each point is draws each row as an observation (T399) and has always drawn its outliers; the mock's greyed Outliers would change today's drawing, which AC-306 forbids. | Yes: from sheet 11's mock |
| T990-3 a saved choice while Each point is is emptied (AC-591) | A box plot saved with Beeswarm or Violin then has Each point is removed. What shows and what's drawn? | **The choice stays in the options; while Each point is is empty the box plot is drawn, and the controls show it, as Outliers with no Violin (`drawnDistribution`). Setting Each point is again brings the choice back.** Lane CHARTS-B's call, overturnable. | The disabled controls must show what is drawn; keeping the choice means emptying a well and refilling it loses nothing. | No |
| T973-1 the Map's spec, and no migration step (AC-622, AC-305) | Where do the boundary set and layers live, and how does a country map saved before R81 become a Map? | **The Map's own settings are `options.map` (`{ boundarySet, points?, density? }`), sparse, read and written by the Map's module in core (`CHART_TYPE_MODULES.map`, the type's name as its options key); `boundarySet` is `countries`, `admin1` or `custom:‹id›`. The Regions layer is the chart's Dimensions (its region key) coloured by its Metrics, as the country map took them, so its Cube query is unchanged; Points (a geo dimension, sized by an optional measure) and Density (a geo dimension) are in `options.map`. A saved country map has no `options.map` and reads as Regions on Countries: no migration step and no `CHART_DOCUMENT_VERSION` raise; `chart-migrations.test.ts` proves versions 1 and 2 of a country map open so.** Lane CHARTS-B's call, overturnable. | A version raise would make every reader and fixture move for a reading that needs no rewrite; keeping Regions on the wells keeps a country map's query, tooltip, marking and unplaced codes as they are. | No |
| T973-2 a boundary set not drawn yet (AC-622) | Admin-1 and custom sets are offered from T973 but drawn from T975 and T979. What does a Map on one draw meanwhile? | **No region, and "Admin-1 boundaries are not drawn yet." or "Custom boundary sets are not drawn yet." in the chart, `text-secondary` 12 px; no code is called unplaced against the countries. Points and Density settings change nothing drawn until T976 and T977.** Lane CHARTS-B's call, overturnable; it goes once T975 and T979 draw them. | Drawing the countries for an Admin-1 choice would draw something the spec didn't ask for (as T934's "not drawn yet" tile says for a type). | No |
| T973-3 the Map's wells (AC-622) | Design 23 sheet 6 draws Boundary set as a select and each layer as a well. How are they built, and what does a type's wells module get? | **Boundary set is a native select (Countries; "Admin-1, by country"; a Custom group listing the folder path's sets, none until T979). Each layer is a well headed "Regions layer", "Points layer", "Density layer": Regions reads "‹key› coloured by ‹measure›", or "Put a region key in Dimensions and a measure in Metrics."; Points and Density take a geo dimension (`type: geo`) from a "+ location" picker, and Points one measure "sized by" it. `TypeWellsProps` gains optional `options`, `onOptions`, `available`, `titleOf` and `spec`, which the editor fills for every type.** Admin-1's country is chosen with T975. Lane CHARTS-B's call, overturnable. | The wells read as the sheet draws them while the Regions layer stays on today's wells; the extra props are what any type's own wells need, so lane A's types can use them too. | No |
| T981-1 parallel coordinates' wells and spec (AC-597) | Design 23 sheet 7 draws Line by, Metrics, Colour and Scale as wells. Where does each live? | **Line by is the chart's first dimension and Colour its optional second, the axes its measures in Metrics' order, so the one grouped Cube query is the editor's as it is. The type's wells name them ("Line by", "Colour", "Axes": "Revenue → Margin % → …"), as T973-3 does for the Map's Regions; with fewer than 3 measures, "Axes" says AC-597's sentence with "+ Measure", which adds one to Metrics. Scale is radio buttons, "Each axis, min to max" (default, stored as nothing) and "Shared", stored as `options.parallel.scale`. `TypeWellsProps` gains `formats` and `onAdd`.** Lane CHARTS-B's call, overturnable. | No dimension well is relabelled in the shared `Wells.tsx`; the type's wells say which dimension is which. | Yes: a segmented Scale drawn as radios, as T990-4 |
| T981-2 "one format" and Shared's reason (AC-597) | When do measures share a format, and what does the disabled Shared say? | **Two measures share a format when the model gives them the same one: a format name (`currency`, `percent`), a described format's name (`currency_0`), or none ("plain numbers"). Otherwise Shared is disabled, described by "Shared needs every measure in one format; these are in ‹formats, in order›." A stored Shared that the formats refuse reads, and is drawn, as Each axis.** Lane CHARTS-B's call, overturnable. | AC-597 names no reason's words; naming the formats says what to change. Reading a refused Shared as Each axis means a later format change never draws a misleading shared axis. | No |
| T990-4 the controls' form and place (AC-591) | Sheet 11 draws Points as a segmented control and Violin as a switch, among the wells. Where and how are they built? | **On the Customize tab, its own Distribution section after Whiskers, a box plot's alone: Points as radio buttons as Whiskers' are, Violin as the tab's switch-styled checkbox with "where values gather"; the reason once below them, each disabled control described by it (`aria-describedby`). The component lives at `editor/wells/boxplotDistribution.tsx`, as T990 names it, and `CustomizeTab` renders it (no new CSS).** Lane CHARTS-B's call, overturnable. | direction.md §7i "Where each surface lives": Points and Violin are on the Customize tab. Radios match the tab's existing Whiskers group, and wiring it there is what puts AC-591 on the real surface. | Yes: radios, not a segmented control |
