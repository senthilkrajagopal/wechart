# Lane SQL's design decisions

Lane SQL's calls since T805, kept apart so lanes don't conflict; the earlier ones, and everyone else's, are in [decisions-2026-10-08.md](./decisions-2026-10-08.md) under "Later decisions".

| ID | Question | Decision | Why | Departs |
|---|---|---|---|---|
| T805-1 the schema browser in the left pane (AC-386, design 17 C, C5) | Is the left pane's browser a new tree or the data source page's? What does it show on Cube Store, on an off source, or with no source chosen? Where does a chosen name go? | **The data source page's tree (T539), shared, under the pane's own "Schema" heading, so T806 and T807 extend one tree for both places. On Cube Store, C5's note as built: "Cube Store has no catalog to browse. Its tables are listed in information_schema.tables and system.tables." 17-P3's Insert a SELECT of information_schema.tables is a proposal and isn't built. An off source, or none, shows nothing under Schema. A chosen name goes into the tab that was open when it was chosen, at its cursor, once: opening that tab again doesn't put it in twice.** Lane SQL's call, overturnable. | Design 17 says the tree "moves" to the left pane (screen 1, C), and C5 keeps Cube Store as built. | No |
| T806-1 Find a table's small rules (AC-448, design 17 pin 4, C3) | Which pages count as unread? What shows while finding? How are the keys named to a screen reader? | **Unread means a schema never opened, or one with pages still to show; while either holds, the box says "Searching the n tables read". While finding, every schema row stays, so an unread one can still be opened; an opened schema shows only its matching tables, then its "Show n more tables" row. With no match, "No table read so far matches “‹text›”." C3's "Read the other 312" isn't built: the schema's own "Show n more tables" reads them. A column's accessible name adds ", primary key" or ", foreign key to ‹schema.table›"; the visible PK and FK tags are hidden from it, and the FK's tooltip reads "References ‹schema.table› (‹column›)".** Lane SQL's call, overturnable. | AC-448 names the sentence, not which schemas count; C3 draws one schema. | No |
| T807-1 a table's ⋯ (AC-449, design 17 pin 6, C1, C2) | What is the preview tab called? What does a Preview do while another run goes? Where is the ⋯ in the tab order? How are names written? | **Preview's tab is named after its table ("orders"). While another run goes, its tab opens holding the SELECT under the hold note and doesn't run later on its own, as any held Run. The ⋯ shows on its row's hover or focus and is in the tab order only on the row that holds the tree's stop, so Tab from that row reaches it; no new key. Names go in unquoted, as the tree lists them (T539's call): one its dialect must quote is quoted by hand. With no columns read, Insert SELECT writes `SELECT *`. Oracle gets the 12c `FETCH FIRST` form, since a source's version isn't known.** Lane SQL's call, overturnable. | Design 17 draws the menu (C1) and the inserted text (C2), not these. | No |
| T808-1 what autocomplete offers (AC-456) | Which names does the list offer, and where do they come from? Are keywords offered? | **Only the names the schema browser has read for the tab's source, at its latest settings version: nothing is asked for anew. Each schema's tables are offered by their own names as well as after `schema.`, since a driver's default schema isn't known; a table named like a schema is offered under the schema only, and one in two schemas offers both's columns. A table's alias in its FROM reaches its columns. A name the dialect must quote goes in quoted. No SQL keywords: AC-456 names schemas, tables and columns. Cube Store, with no catalog, offers nothing.** Lane SQL's call, overturnable. | AC-456 says "from the names introspection has read". | No |
| T808-2 autocomplete's keys (AC-456, R75) | Which keys does the list take, and when? | **Only AC-456's: ↑ and ↓ choose, Enter accepts, Esc closes the list and its key goes no further; each only while the list is open. The library's Ctrl-Space, Alt-\`, Alt-i, Page Up and Page Down aren't bound (R75). The list takes keys as soon as it shows, not after the library's 75 ms, so Enter never adds a line while the list is open.** Lane SQL's call, overturnable: the 75 ms guard against a key pressed before the list is seen could come back if the user prefers it. | AC-456's "Fails when: Enter adds a new line while the list is open". | Departs from the library's default `interactionDelay` |
| T809-1 the parameters strip's small rules (AC-453, design 17 pin 13, F1, F2) | What does each type's value field look like? What does a type change do to the value? Which parameters hold Run? | **Text is a text field, Number a number field, Date a date field, and Boolean two buttons, true and false, neither pressed at first (F2). Changing a type clears the value, which may not fit the new type. A value is held as text, and empty means no value. Run is held, button and ⌘/Ctrl+Enter alike, while any parameter the tab's SQL lists has no value, not only those in the statement that would run, and the run bar says "Give ‹a, b and c› values to run" (F1). With none, the strip reads "No parameters" (F3). A parameter's type is kept with the tab, in this browser (AC-451). Until T811 binds values, a run sends the SQL with its `{{name}}`s, and no value is written into it.** Lane SQL's call, overturnable. | F1 and F2 draw the fields and the sentence; AC-453 says "until each has one". | No |
| T810-1 parameters on Dremio and Cube Store (AC-482, design 17 F4, F5) | What does the API answer? Is the strip shown? How does the API find a parameter? | **The API refuses a run holding a `{{ name }}` on Dremio or Cube Store with a 400, `outcome: 'refused'`, before xcube is asked and with no audit event, as other requests it refuses before a run. Its words are F4's: "Parameters aren’t available on ‹Dremio | Cube Store›. Write the value into the SQL to run it here." The browser holds Run with the same words and shows no strip there (F5). Both ends use one finder, `@wechart/core/sql-parameters`, and the API reads both sources as standard SQL, which lang-sql's own dialects don't cover.** Lane SQL's call, overturnable. | F4 and F5 draw the browser's side; AC-482 says "never write a value into the SQL text". | No |
| T811-1 AC-465's values half (AC-454, AC-465) | T811 cites AC-465's "choosing a History row puts its values into the tab", but History's list (T817) and choosing a row (T818) aren't built. Where does that half go? | **T811 builds AC-454 in full, and History keeps each run's values for its owner (`GET /api/sql-runs` answers `parameters`). Choosing a row and putting its values into the tab moves to T818, which builds the choosing. AC-465 stays open.** The coordinator agreed, 2026-10-18. | A test can't choose a row that no screen shows. | No |
| T811-2 the audit's SQL for a bound run, and the run's body (AC-454, AC-382) | xcube's `redactedSql` for a bound run is the statement as it ran, with xcube's own placeholders (`$1::text`), not `{{name}}`. How does the audit keep `{{name}}`? What does the browser send? | **The API turns xcube's placeholders back into `{{name}}`, numbered by each name's first place as xcube numbers them, the SQL read in the driver's dialect where lang-sql has one (PostgreSQL for PostgreSQL and Redshift, SQL Server's; `parameterNamesOn`), on every answer but a refusal of the parameters themselves, so a write refused once bound is said with its `{{name}}`s too: ` $n::type ` on PostgreSQL and Redshift (the cast and the two spaces xcube wrote go too), `@pn` on SQL Server and BigQuery, and `:pn` on Oracle, inside any cast xcube wrote. MySQL's and Snowflake's `?` can't be told from a redacted literal, so they stay `?`. A refused run's `redactedSql` is the SQL as sent, so it already has its `{{name}}`s. The browser sends `parameters: [{ name, type, value }]`, the saved query's shape, for only the names in the statement that runs, since xcube refuses a value used nowhere. A Boolean's value is "true" or "false", sent to xcube as itself. The API refuses a malformed list before xcube is asked, and refuses any value on Dremio or Cube Store (T810). xcube's parameter refusals are shown in its own words, which name a parameter, never its value; the audit line reads "Not run · its parameters were refused".** Lane SQL's call, overturnable. Asking xcube for a `redactedSql` that keeps `{{name}}` would make it exact on every driver. | Design 17's "the audit keeps `{{name}}` only"; research `xcube-bb188d8ada.md`. | No |
| T813-1 the Saved tab's small rules (AC-458, design 17 I1, I3) | How is the list ordered? What does Undo do? What do Open, Duplicate and Rename… do to tabs? Where does the list sit until History is built? | **By name, ignoring case, under "Only me · by name". Each row's name is a button that opens it, as Open on its ⋯ does. Under the name: the source as "‹name› · ‹place›" (the picker's place), or "A data source no longer available to you" for one the user can't run SQL on, never naming it; then the person icon and "Only me", and "n parameters". Delete answers the query whole, and the toast's Undo saves it again under its own id. An id anyone holds is refused alike ("That saved query can’t be brought back."), saying nothing of whose it is. Open opens it in a new tab named after it, with its SQL, parameters, types and saved state, on its source where the user still has it and otherwise on none (T814 words that). A tab already holding it is selected instead. Duplicate saves "‹name› (copy)", or the first free "(copy n)". Rename… is a dialog with the name, its refusal shown in it as Save…'s is; tabs holding the query take the new name for their Save, and a tab still named after it is renamed too. A deleted query's open tabs are left as they are. Until T817 builds History, the right pane holds the Saved list under its "Saved and History" head, with no tabs.** Lane SQL's call, overturnable. | I1 draws the rows and the ⋯, I3 the toast; AC-458 doesn't order them. | No |
| T812-1 Save…'s small rules (AC-457, AC-483, design 17 pin 10, I2, I6) | Who may save? Is a name trimmed, and are names unique case-sensitively? Where do the buttons go? What does a duplicated tab keep? | **Any signed-in user may save a query of their own; the API checks no data source, since a saved query is only text kept for its owner, and opening one is held to the source's rules (T814). Names are trimmed, and unique to their owner as typed, case-sensitively. The refusals read "Give the query a name.", "A name is at most 100 characters.", "You already have a saved query named “‹name›”." and "A description is at most 1,000 characters.". The buttons go in a row over the editor: Save… on a new query; "Saved query · Only me", Save and Save as new… on a saved one, as pin 10 draws them. A duplicated tab is a new query. "Changed since saved" (17-P1) isn't built.** Lane SQL's call, overturnable. | I2 draws the dialog and one refusal; AC-483 says only "with the reason". | No |
| T814-1 a saved query whose source the user can no longer run SQL on (AC-459, design 17 §5) | What counts as "can no longer run SQL on"? What does the API answer, and how do Rename…, Duplicate and Undo keep the source the owner isn't told? | **A source counts while the picker lists it for the user and not off (`runsSqlOn`, from `GET /api/sql/sources`'s own rule): one switched off, one whose folder access they lost, one deleted, and another workspace's all count as lost. `GET` (one and the list), `PUT` and `POST` answer such a query with `sourceId: null`, never its id or name. A save sending `sourceId: null` means "the one it was saved with": `PUT` keeps the stored source (Rename…), and `POST` takes the source of `from`, another of the owner's saved queries (Duplicate); with neither, it is refused as before. `DELETE` still answers the query as kept, its source id included, for Undo alone; it is never shown. Opened, the tab has no source and reads "Choose a data source: the one it was saved with isn’t available to you." until one is chosen; that is kept with the tab in this browser. With no data sources here (no SQL runner), each query is answered as kept.** Lane SQL's call, overturnable. | AC-459 names the sentence and "never naming it"; the Saved tab's Rename…, Duplicate and Undo (T813) must still work on such a query. | No |
| T815-1 saved queries in ⌘K (AC-460, design 17 I5) | Where do they come from, how do they match, where do they sit, and where does one open? | **The palette asks `GET /api/sql/saved` as it opens, which answers the owner's alone, so nobody else's can be listed; `/api/search` (Explore's) still holds none. A query matches on its name, case-ignored, as the catalog's titles do. They come first, as I5 draws them, each as "Saved query", its name, and its source's name as the second line, which the API now answers as `sourceName` only for a source the user may still run SQL on, so a lost one has no second line. The palette keeps its one flat list with the type as a word, not I5's group heads. Choosing one goes to `/sql?saved=‹id›`, which opens it as the Saved tab's Open does (its own tab, or the one already holding it), and the address then names that tab. The API checks only the sources the user's saved queries are on, not every data source, since ⌘K asks on every opening.** Lane SQL's call, overturnable. | I5 draws the rows; AC-460 says "labelled "Saved query"". | Departs from I5's group heads: the palette has none for any type |
| T816-1 ⌘/Ctrl+S and ⌘/Ctrl+F's small rules (AC-455, R75, R78) | Which keys exactly, where, and what do they do when there is nothing to save? | **⌘/Ctrl+S is heard on the workspace's own element, so focus anywhere in it counts (the panes, the editor, a dialog in it), and nowhere else. It takes S with ⌘ or Ctrl, without Shift or Alt, outside an IME composition. On a saved query it is Save; on a new one it opens Save…; while Save… is open, or with no source chosen, it does nothing but keep the browser from saving the page. ⌘/Ctrl+F is the editor's own, in the SQL runner workspace's editor only (the data source page's SQL tab keeps the browser's find): `@codemirror/search`'s panel at the top, focus put into its field, and Esc closes it. The search keymap's F3, Mod-g, Mod-d, Mod-Shift-l and Mod-Alt-g aren't bound (R75); Enter and Shift+Enter in the panel's own field are the panel's.** Lane SQL's call, overturnable. | AC-455 names the two keys and "nothing new outside the workspace"; research `keyboard-shortcuts-sql-runner.md` says the page hears both first. | No |
