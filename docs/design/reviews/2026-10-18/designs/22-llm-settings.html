Security › AI: the Super-Admin's provider settings for Copilot, built now for the Text tile's summaries

R80: "AI-written narrative in rich tiles? A: 'Now, with LLM settings'. The Super-Admin provider, model and key settings (from the parked copilot) are built in this round." This page is that part of references-copilot.md §9, adapted to what summaries need now and kept ready for the copilot chat when it's taken up: the same provider, key and limits.

This design draws:

  • The page: AI on or off; who may use it; the provider, endpoint and model; the API key, stored and never shown; usage limits and the message people see at one; what is sent to the provider; Test connection; usage this month.
  • Where it lives: a fifth tab in Security, after Access tokens, for Super-Admins only.
  • States: first setup with a failing test; replacing the key; each test result; turning AI off; groups; limits as people meet them; unsaved changes; the audit trail; narrow windows; usage empty and loading.

Screens are Ada Admin, a Super-Admin. Screen 1 is the page set up and working, with one change unsaved; screen 2 is the first setup, with the key refused.

What doesn't change: Security's other tabs (designs 08 and 18); the account menu; how data-source credentials are kept (sealed to xcube, R27), which this key isn't part of (Q3); the audit trail's table, which gains events (state H).

Screen 2: setting it up the first time

A first setup is a data-source connection by another name: fields, a secret, a test that must pass. It works the same way, so a Super-Admin who has added a data source already knows it.

  1. 1
    "Test failing · not saved"Before anything is saved, the chip reads "Not set up", with the off icon (state A). After a failing test, it says so. Authors see no Copilot until a setup is saved.rule 3
  2. 2
    Save held, and whyThe reason sits beside the button, not in a tooltip. Discard throws away every unsaved field, the typed key included, and asks first (rule 85).rules 23, 35 · rule 143 (new)
  3. 3
    The key, typed onceA password field: its characters never show, no "show" toggle, no paste-back. It goes to wechart's API only to test and to save. The field is outlined in status-error because its check failed.rule 83 · rule 142 (new)
  4. 4
    A failed check says what failedOne sentence, the provider's status, what to check, and Details (the provider's error text, never the key, no stack trace). Later checks show "not run" with their own icon, not as failures.rule 104's pattern · rule 144 (new)
  5. 5
    Test againRuns every check in order, each showing Running as it goes (state C). Focus stays on the button; the result is announced politely.rule 85

D · Turning AI off

An unsaved switch; the line under it says what Save will do. No confirmation dialog: it's a reversible setting, saved with the rest.

AI is off · once saved
When saved: no one can draft summaries. The 38 summaries already in Text tiles stay, with their labels; their "Review" is unavailable until AI is back on. Settings, key and limits are kept.
