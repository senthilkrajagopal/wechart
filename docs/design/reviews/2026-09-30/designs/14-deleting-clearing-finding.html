Deleting, clearing and finding — delete what nothing uses, clear My workspace, a folder per edit, Explore by kind

None of this is built. R48 asks for it, and F39's criteria define it (AC-362 … AC-370). Today nothing is deleted from Explore: its row menus offer Rename, Move to…, Propose… and Export…, and a model row has no menu at all. A library chart's page has a Delete chart button in its own section of the details pane. It asks "Delete this chart?" when dashboards use it, then deletes it anyway (AC-023, now retired). A data source's page offers only Discard my copy…, for a workspace copy. Dashboards, models and folders can't be deleted anywhere.

This design adds:

  • Delete… as the last entry of each item's ⋯ menu, set apart in the error ink, for those who may change its folder. Deleting needs no proposal (AC-291).
  • A check first. Choosing Delete… asks what depends on the item. If something does, a Can't delete dialog names what you may see, each as a link, and counts the rest, and nothing is deleted. If nothing does, a short confirmation deletes it.
  • Folders: Delete is offered only on an empty folder.
  • My workspace: Clear My workspace…, naming every open proposal it withdraws.
  • A project folder per Edit in my workspace, with a description under its name, and a description for every folder.
  • A kind filter over the open folder in Explore.

Screen 1 is Wren Writer, a read-write member of Sales / EMEA, in Explore with sign-in on. Screen 2 is Wren deleting the library chart Top products, which dashboards still use. States A–I follow the criteria in order, one letter per criterion from AC-362 to AC-370.

What doesn't change: Rename and Move to… in the row menus; the header's Rename and Access; New; the search; the workspace band; origin and target lines (design 04); Export… (design 13); and Discard my copy… on a data source's workspace copy (design 03).

A folder that holds something: no Delete, rather than a greyed-out one

The brief asked for one of the two, justified from the references. The drawn choice is to leave Delete out of the menu.

QuestionA greyed-out Delete with the reasonNo Delete (drawn)
What the spec saysAC-366: "Explore SHALL offer Delete on a folder only when it is empty", and it fails when "Delete is offered on a folder that holds something". A greyed item is still in the menu, so the reading is doubtful. T521's planned test reads it strictly: "Delete is in an empty folder's menu and not in one that holds something".Meets the criterion and its test with no reading needed.
How this product's menus behavedirection.md greys choices in two places. Chart types that don't apply are greyed, with the requirement on hover (§6, the Tableau Show Me pattern), and illegal wells show why during a drag (rule 12). In both, the user is comparing alternatives side by side, not reaching for one command.Menus and headers leave out what can't be done. A shared folder's New offers Folder only, rather than greyed kinds (design 04, state C; AC-192). A data-source row has no Rename or Move, because its page handles them (FolderContents). A reader gets no changing action at all (rule 68).
Where the reason isIn the menu item, at the moment of choosing.Already on screen. The row's Built on says "4 items", and the tree counts them (AC-193, AC-194). Opening the folder lists them. Once it's emptied, its row and header both offer Delete….
A folder that fills while you look—If someone adds to the folder after the menu opened, the delete is refused, naming what it now holds (state E4, AC-366).

Keyboard and accessibility

Rule 85 and principle 5, applied to every new dialog and control. Every control is a native button, link, radio button or text field, so each takes the same focus ring. No key deletes or clears anything on its own.
