Personal access tokens for MCP — make one, see it once, list and revoke your own; Super-Admins list and revoke everyone's; and how to connect Claude Code and Claude.ai

R78 adds an MCP server so Claude Code, Claude.ai and Claude Desktop can read wechart, edit in My workspace and propose, as the person whose token they hold (F41, AC-430 … AC-445, AC-468 … AC-479). Nothing of it is built. The server itself has no screen: these are the screens a person uses to give a client access, and a Super-Admin uses to oversee it.

This design draws:

  • Access tokens, the person's own page, from a new entry in the account menu: their tokens with name, scopes, when made, when it expires and when last used, and Revoke (AC-430, AC-431).
  • New token: a name, the three scopes with Read always included, and a lifetime of 7, 30 or 90 days, 30 to start (AC-430, AC-468, AC-469).
  • The token, shown once, with Copy, and the Claude Code command ready to paste. It is never shown again, to anyone (AC-430).
  • Security › Access tokens, for Super-Admins: every user's tokens, never their text, with Revoke (AC-470).
  • How to connect, for Claude Code and for Claude.ai and Claude Desktop custom connectors (AC-444, AC-445), with the limits a client meets (AC-472, AC-475).
  • States: empty, loading, error, expired, revoked, never used, sign-in off, the audit events, and narrow widths.

Screens 1–3 are Wren Writer, a read-write member of Sales / EMEA, making a token for Claude Code. Screen 4 is Ada Admin, a Super-Admin, revoking one of Wren's tokens. Sign-in is on. States A–J follow the brief's order.

What doesn't change: the account menu's identity, Super-Admin badge and Sign out (design 09, as built at T696); Security's Policies, Preview as groups and Audit trail tabs (design 08), whose trail gains the events in state I.

Your deployment's MCP address. It serves only /mcp, over TLS.

Claude CodeClaude.ai and Claude Desktop
  1. Make a token with New token. Give it the scopes the work needs.
  2. Add wechart to Claude Code, in a terminal: 
    claude mcp add --transport http wechart https://mcp.wechart.example.com/mcp --header "Authorization: Bearer ‹your token›"
  3. Check it: ask Claude Code to list your wechart folders.

The token goes only in the Authorization header. wechart refuses it anywhere else, in the URL included.

What a token can do

  • Read: list folders and items, read definitions, query cubes and views. Always included.
  • Workspace edit: change things in My workspace only.
  • Proposals and jobs: propose, withdraw, Run now and Cancel.
  • Never: approve or reject; change a data source; run SQL; read the audit trail; make or revoke tokens.

Limits

  • 60 calls a minute per token, set by your deployment.
  • Up to 1,000 rows and under 50,000 characters per answer, with the next page on request.
  • Every call is recorded in the audit trail with the token's name, never with what it asked for.

Proposals, and questions for you

The screens draw what F41 asks of a page, with R78's answers. The proposals go beyond it. The questions are gaps the spec doesn't settle; each is drawn one way, and the way drawn is only a default until you decide.

Proposals: adopt or not

#ProposalWhyWhere
P1In Security › Access tokens, a row's "Show its calls" opens the audit trail filtered to MCP calls by that token.AC-478 records every call with the token's name. A Super-Admin deciding whether to revoke a token wants to see what it has been doing, in one step.screen 4 pin 5
