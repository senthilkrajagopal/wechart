The SQL runner workspace — a data source picker and schema browser, tabs bound to a data source with typed parameters, Saved and History, and a cube or a chart made from a run

R78 moves the SQL runner out of each data source's page and into a workspace of its own, after Schedules. F42 defines it (AC-446 … AC-467, AC-480 … AC-483), and AC-001, AC-373, AC-381, AC-385, AC-386 and AC-387 are amended for it. Today the runner is the sixth tab of a data source's page (design 15, as built in SqlRunner, SqlEditor and SchemaBrowser).

This design draws:

  • SQL runner in the switcher, after Schedules, for Super-Admins and read-write members (AC-001, AC-446).
  • The three-pane workbench of direction §2. On the left, the data source picker, with its "Cube" group, and the lazy schema browser with Find a table and PK / FK tags. In the centre, tabs bound to a data source, each with the run line, F40's warning, the CodeMirror editor, the typed-parameter strip, the Run bar and the result grid. On the right, Saved and History.
  • Make a cube… and Make a chart…, a docked 480 px pane that adds a draft cube to My workspace.
  • The data source page's "SQL runner" tab, which keeps the switch and gains "Open in SQL runner", and no longer holds an editor.
  • States: empty, loading, running, cancelled, capped, error, lost access, a parameter held on a source that can't bind it, the "Cube" group, and widths below 1,280 and 1,024 px.

Screen 1 is Wren Writer, a read-write member of Sales / EMEA (group sales-emea-rw) and of Finance, just after a run on emea_replica, with sign-in on. Screen 2 is Wren making a cube from that run. States A–O follow the brief's order, and each names its criteria.

What doesn't change: every F40 safety rule, per run (the switch and its attestation, SELECT and EXPLAIN only, the read-only transaction, 10,000 rows, 10 MB, 30 seconds, one run per person, the audit, the warning); the switch dialogs of design 15 (screen 2, G and H); the run labels of design 15; the audit trail (design 08), which keeps its "SQL run" event.

Screen 1: what changes, and why

The runner leaves the data source's page for a workspace of its own, laid out as direction §2's workbench: a typed tree on the left, the work in the centre, and a docked pane on the right. Every editor tab is bound to one data source, so Wren can keep a query on emea_replica, one on fx_warehouse and one through Cube open at once, and see all of her runs in one History. What the run reaches, as whom, and what it bypasses stays above every tab's editor.

Proposals, and questions for you

The screens and states draw what F42 and the amended F40 criteria ask for, with R78's answers. The proposals go beyond them, to adopt or not, and nothing above depends on them. The questions are gaps the spec and the design study don't settle. Each is drawn one way so the design is complete, and the way drawn is only a default until you decide.

Proposals: adopt or not

#ProposalWhyWhere
P1"Changed since saved", an icon and a label beside "Saved query · Only me", when the tab's text or parameters differ from the saved query.Save on a saved query overwrites it (AC-457). Without a marker, nothing says whether there is anything to save, or that closing would lose a change.I6
P2A one-time note, the first time a tab is opened, that open tabs are kept in this browser only.R78 chose "Browser only". Someone moving to another machine would otherwise look for tabs that aren't there. Saved queries and History do follow them.D5
P3On Cube Store, where there's no schema browser, a button that inserts a SELECT of information_schema.tables.The built note names where Cube Store's tables are, but the person still has to type the query. It inserts and doesn't run, like Insert SELECT.C5
