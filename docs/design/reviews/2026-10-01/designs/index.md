# Designs for approval — UI design 2026-10-01 (phase 2)

One static mockup for R50, the SQL runner (F40, AC-373 … AC-385). It is numbered after design 14 in `../../2026-09-30/designs/index.md`.

- **Format:** the same as the 2026-09-27, 2026-09-28 and 2026-09-30 designs. It's a self-contained HTML file with inline CSS in direction.md's tokens, and Inter and IBM Plex Mono from Google Fonts, with no other requests. Open it in a browser. It shows:
  - two 1440 × 900 screens with numbered pins, each followed by the notes on its pins;
  - states A–J, one letter for each part of the brief, each naming the criteria it shows;
  - the keyboard and accessibility rules, and every new state as an icon and a label;
  - the proposals and questions.
- **Where it comes from:** R50 and §P2.6 J in `docs/requirements.md`, F40 in `docs/spec.md`, `docs/research/sql-runner.md` (Cube Cloud's SQL Runner and Superset SQL Lab), and the approved designs it builds on:
  - 03: the data source's page and its five tabs, as built in `SourceSettings`;
  - 04: My workspace's band, and a copy's origin and target;
  - 08: the audit trail's filters, table and inspector, as built in `AuditTrail`;
  - 14: the data source header's ⋯, and the style of its dialogs and decision table.

  It adds one tab to what's built, and changes nothing on the other five.
- **Illustrative content:** people, folders, data sources, SQL, rows, error texts, times and counts are illustrative.
- **Build note:** running, cancelling and the caps need an xcube route that doesn't exist yet: one statement on a dedicated connection, the read-only transaction, at most 10,000 rows, 10 MB and 30 seconds, and a cancel by run (research §7). It's asked of xcube through the exchange, and the tab is built against xcube's published image. wechart's server decides who may run, enforces one run per person, keeps My runs, and writes the audit event.
- **Proposals:** P1 is the decision the brief asked for: whether the tab is hidden or shown when the runner is off. P2–P5 go beyond AC-373 … AC-385. The states don't depend on any of them.

## Questions for you

Each is drawn one way so the design is complete. The way drawn is only a default until you decide; "Not drawn" means no default is shown.

- **Q1. ⌘/Ctrl+Enter with text selected.** Does it run the selection or the whole text? Only one statement runs at a time, so a selection is how you'd keep several queries in the editor.
  - Drawn: the selection when there is one, with Run reading "Run selection"; otherwise the whole text.
- **Q2. What My runs shows on a data source's page, and how many at once.**
  - Drawn: this data source's runs by default, with All for every data source; 50 at a time, newest first, with Show older runs, back as far as the audit retention.
- **Q3. The warning: where it sits, and whether it can be hidden.**
  - Drawn: always shown, above the editor, with no way to hide it.
- **Q4. A later approved version changes how the data source signs in** (a new user, a new host, or a replaced password). The confirmation was given about the old login. Does the runner stay on?
  - Not drawn. The options: it stays on, or it turns off until a Super-Admin confirms the new login.
- **Q5. Which types head the columns:** the database's own type names, or Cube's general ones?
  - Drawn: the database's own, such as `int8`, `numeric` and `timestamptz`.
- **Q6. Rows that arrived before a stop.** When a run is stopped at 30 seconds, or cancelled, after some rows have arrived, are they shown?
  - Drawn: no, "Nothing came back".
- **Q7. Cube Store and workspace data sources.** AC-384 lets "those who may run SQL on some data source" use Cube Store, and every owner of a data source in My workspace may run SQL on it (AC-383). Do they count? If so, nearly every read-write member could read every folder's rollups.
  - Drawn: they don't count. Only being allowed on a data source in a folder, one a Super-Admin has switched on, gives Cube Store.
- **Q8. A workspace copy pointed at another database.** A copy keeps its original's stored password, which is bound only to the host and port (AC-312; research §5 S4). Its owner can change the database, or the role on Snowflake, test it, save it, and run SQL with no switch, reaching data the original never pointed at with the same login.
  - Drawn: as decided (R50-6), always open to its owner. The alternative: a copy whose database, user or role differs from its original's needs the switch.
- **Q9. What a Super-Admin confirms for Cube Store.** Cube Store has no built-in authentication (research `cube/refresh-jobs-caching.md`), so there's no login whose grants can be confirmed, as AC-374 asks.
  - Drawn: they confirm that what wechart reaches Cube Store with can only read, and that everyone allowed may read every folder's rollups, with wechart's command check as the only guard. The alternative: no confirmation for Cube Store, with AC-374 amended.
