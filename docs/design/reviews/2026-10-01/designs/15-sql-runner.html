The SQL runner — read-only SQL on a data source's own connection, from a SQL tab beside its settings

None of this is built. R50 asks for it, and F40's criteria define it (AC-373 … AC-385). Today a data source's page has five tabs: General, Connection, Test history, Usage and In Cube (design 03, as built in SourceSettings). Nothing in wechart runs SQL that a person writes, and xcube has no route that does (research sql-runner.md §7).

This design adds:

  • A SQL tab, last on each data source's page, for Super-Admins and the read-write members of the data source's own folder. It has the warning, where the SQL runs, an editor, Run, the limits, the result as a grid with Download CSV, and the person's own runs beside it.
  • A switch per data source, off to start, that only a Super-Admin turns on, after confirming that its login can only read. Who confirmed it, and when, is kept and shown.
  • Your own data sources in My workspace, which you may run SQL on with no switch.
  • Cube Store, listed among the root's data sources once a Super-Admin turns it on, for SELECT, SHOW, DESCRIBE and EXPLAIN only.
  • An audit event for every run, with the SQL's literals replaced.

Screen 1 is Wren Writer, a read-write member of Sales / EMEA (group sales-emea-rw), on emea_replica's SQL tab just after a run, with sign-in on. Screen 2 is Ada Admin, a Super-Admin, turning the runner on for emea_replica. States A–J follow the brief's order, and each names its criteria.

What doesn't change: the other five tabs; the page's header and its line (design 03 as built, with design 14's ⋯); Edit in my workspace and History; the workspace band; and the audit trail's filters, table and inspector (design 08).

E · Refused before running, and a database error (AC-375, AC-376)

wechart reads the SQL before sending it. Anything but one SELECT, which may start with WITH or use UNION, or one EXPLAIN without ANALYZE, is refused, and nothing reaches the database. The refusal says only SELECT and EXPLAIN run, and names what it found. The database's own errors come back as it gives them, with any stored secret replaced by [redacted].

What each part does

This data source is the default on a data source's page (Q2). All names each run's data source and folder. A run on another data source opens that data source's SQL tab with its SQL in the editor. Refused runs are listed too, as "Not run", with the kind of statement found, so the SQL can be fixed and run again.
