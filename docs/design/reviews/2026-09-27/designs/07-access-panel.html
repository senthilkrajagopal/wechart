The Access panel — who reaches this folder, set here or from above, and one Add per list

The panel is built (T330) and works: counted Save, outranked notes, Undo. Its layout doesn't read (UX-250, UX-251). One shared "AD group / Access / Add" form sits below both lists, with inline 14 px labels and a native select for the level. There's no help text for what each level allows, no footer saying changes are audited, and no Cancel. The group box offers no suggestions when it's focused. This redraws the panel to references.md surface 2 and rules 62–66, keeping its behaviour.

What changes, and why

Each list reads top to bottom: what the level allows, the groups set here (removable), a way to add one, then the groups that reach it from above (locked, with their source as a link). It's what AC-260 asks, laid out so an admin can walk up the chain.
