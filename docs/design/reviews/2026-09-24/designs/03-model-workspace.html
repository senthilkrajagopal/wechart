What changes, and why

Structure stays as built (T234, AC-222 … AC-226). The changes are in what the engineer sees before acting, and in how much each row costs to scan.

  1. 1
    The prototype's file tree▾ model/cubes/ and ▾ model/views/ folders, 28 px mono rows, the open file as a full-width accent-soft row (today a 2 px ring box), a Jinja tag on files the form can't open, New cube and New view under the tree. The pane head carries the model's draft state ("All published" or "2 unpublished").UX-075
  2. 2
    A 44 px editor head with a 13 px path and a state"Published · no changes" or "◷ Unpublished changes", then Discard and Save & reload Cube. Today the path is a 20 px title and a clean file says nothing. No History button and no dev-mode badge (the user's decisions).UX-076
  3. 3
    Tabs that fit"Pre-aggs" and "Access" as in the prototype, counts in a muted weight. All eight tabs fit the 676 px form pane; today "Access policy 0" is scrolled out of a 666 px strip with no affordance.UX-074
  4. 4
    Say what the form would drop — before, not duringOn opening a file with comments, Jinja or anchors, the warn bar names each one by its first line and its YAML lines, with "Show in YAML" (scrolls and highlights them, pin 9) and "Edit in form anyway". The app's just-in-time guard ("This edit would drop … Apply anyway / Keep the file") stays as the second line of defence. Direction §7b asks for exactly this naming.UX-070
  5. 5
    Rows that read like the YAMLName in mono with PK / public / format badges, the type on the right, the SQL on its own muted line under the name, rules between rows — the prototype's .mrow. No bordered box per member and no Remove on every row.UX-072
  6. 6
    An expanded member is a short, guided formBasics first (Name, Type, SQL, Title, Format, Description, and switches that show Cube's default: "Public · default on"), with one-line help from the schema; rare keys behind "Advanced". Remove moves into the body, where it is deliberate. The same grouping applies to the General tab (state B).UX-072 · UX-073
  7. 7
    "+ dimension · 3 total" closes the listAs in the prototype; the new member opens expanded with Name focused.UX-072
  8. 8
    YAML | Join diagram, sync note, and soft wrapUnchanged, plus a Wrap toggle (on here) so long descriptions and comments stay readable in the 524 px code pane; today they run off its edge. The form pane is a little wider than the code pane, as in the prototype (1.15 fr : 1 fr).UX-078
  9. 9
    The code shows what the form is pointing atThe expanded member's lines are tinted accent-soft; the comment the form would drop is tinted and flagged in the gutter. The form is flat on the pane — no card inset — which gives back 32 px.UX-070 · UX-077

B · General tab, grouped

Today every key of a cube is an equal field in one column: SQL table as a three-line textarea, Public as a "(not set)" select, no help text, and Extends, SQL alias, Meta and Calendar as prominent as Name.

Grouped as the prototype does: Basics (what almost every cube sets), Refresh (where AC-153's cron editor will live), and Advanced collapsed. "Reads from" makes Cube's either/or explicit instead of two empty boxes. Switches show Cube's default when a key is unset. Help lines come from docs/research/cube/data-modeling.md's schema inventory, so the form states the rule rather than a guess.

Every key the schema accepts stays reachable (checklist 26); only its prominence changes.
