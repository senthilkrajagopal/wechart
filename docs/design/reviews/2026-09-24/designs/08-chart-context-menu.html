A · Drill by ›

The dimensions the marked items can be regrouped by, from /v1/meta. A hierarchy's next level comes first when the tile's dimension is a level of one; the sample model declares none (observed: every cube has hierarchies: []). Then finer time grains, then the cube's own dimensions, then those of cubes joined to it. A cube with no joins, like monthly_orders, offers time only.

Neither the marked member itself nor primary keys are offered: one bar per order is what View marked rows is for.

Proposal — needs the user's approval P1. No criterion covers drilling, although requirements.md lists drill-down as In and direction.md rule 31 describes it.

C · Data as of › — a pre-aggregation served the tile

Everything here comes from Cube's answer and model. The next run is the one thing wechart computes, and it uses Cube's own formula:

• the model name, from usedPreAggregations[…].preAggregationId;
• the last build, from lastUpdatedAt (lastRefreshTime equals it on a rollup-served answer);
• the schedule as written, from /v1/meta?extended's refreshKey;
• the next run, from Cube's turn-over formula (nextRefreshes, T159).

The lateness is refreshLagSeconds' 5½ minutes for an hourly key; AC-153 says "about five". A key the model doesn't declare shows "Cube's default" and no next run, because the default depends on cube-level keys (refresh-key-schedule.md's correction).

Refresh now is AC-148's: past wechart's cache, and still as of the last build. Jobs is where to build now.

Proposal — needs the user's approval P6, including a ?preagg= link that opens Jobs on this pre-aggregation (Jobs keeps its selection in component state today).

E · Export ›

CSV of the tile's table is today's Download CSV (T177, T178): formatted values plus raw numbers, and "cut short" said when Cube's row limit truncates.

CSV of marked rows is AC-114's export, and comes with T120.

Images: wechart draws with ECharts' SVG renderer, so SVG comes straight from the chart, and PNG means rasterising it in the browser (UNVERIFIED; no research yet). KPI, table and pivot tiles are DOM and have no ECharts image.

Excel needs a library, and so a research doc first. PDF isn't offered: server-rendered export is Cube Cloud's, and out of phase 1.

Proposal — needs the user's approval P5: this submenu in place of AC-199's "Download CSV" item, and the image and .xlsx formats.

F · Copy ›

"Copy chart…" can mean four things:

• Copy image: the chart as drawn, marking outline and all. It needs the browser's Clipboard API, which has no research doc yet.
• Copy marked values: direction.md §7a lists it, and the spec has no criterion.
• Copy link with marks: AC-123, T129.
• Copy to dashboard…: puts a local copy on another dashboard the way Duplicate does (AC-062), without opening it in edit mode. Save to folders… (AC-127) stays in edit mode, because it changes this dashboard's chart into a library chart.

Proposal — needs the user's approval P4, except the link, which is specified.
