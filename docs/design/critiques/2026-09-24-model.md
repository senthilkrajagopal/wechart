# Model workspace critique (2026-09-24)

Produced by the `design-critic` agent and saved verbatim, as part of the
prototype-alignment pass the user asked for on 2026-09-24.

**What was compared:** the running app at http://localhost:5400/model (`/model/files/<path>`) and the prototype at http://127.0.0.1:5500/index.html#model (`docs/design/prototype/model.js`, `schema.js`, `index.html`). Both were viewed at 1440×900, in light and dark themes.

**Coverage gap.** I could not see what the app shows when Cube rejects a draft. I made a draft Cube would reject (a measure with `type: summ`) and clicked "Save & reload Cube", the only action that asks Cube to validate. The permission classifier blocked the click as "Modify Shared Resources". Server source (`packages/api/src/model/publish.ts`) says a rejected draft is never written. So AC-136's error display is **not verified here**. I discarded the draft by reloading, published nothing and deleted nothing.

## 1. Summary

1. **The workspace frame has lost its left pane.** The prototype is one three-pane screen: file tree (240 px), Form, then YAML with Problems. The app splits this into two pages. `/model` is a list of file cards, and `/model/files/…` is a two-column editor with no file tree. To change files you go back to the list, and a file with errors has nowhere to show it.
2. **The editor sits on a padded, scrolling page instead of full-height panes.** The app puts a 32 px `h1` and a separate row for the Save button above the panes. The form starts at y=152 against the prototype's y=92, and the page scrolls to 1,048 px against 900. The Problems panel sits under the YAML as a 66 px card, where the prototype docks it at 150 px.
3. **Reference fields are free text, not member pickers.** This affects pre-aggregation measures, dimensions, segments and rollups, the time dimension, join targets, drill members, and view includes and excludes. The app renders them as comma-separated inputs or YAML textareas. Direction §7b says these fields are "member pickers, never free text"; the prototype uses toggle-chip pickers and a cube select.
4. **Member rows are flat and ungrouped.** Collapsed rows have no PK, format or hidden badges and no SQL preview. An expanded row lists every field for every variant at once: Case, Switch, Latitude, Longitude, Values and Multi-stage are all shown on a plain number dimension. It has no groups and is 1,774 px tall. The prototype shows the variant through a "Defined by" segmented control, collapses groups (Basics, Formatting and so on), and hides fields by type.
5. **The header has no draft state.** It has no History, no branch or dev-mode badge, no unsaved or dirty marker, and no Discard. Unsaved edits vanish on reload without warning or recovery. Problems counts errors only, never warnings.

## 2. Findings

### F1. There is no file tree in the editor; the file list is a separate page
- **Prototype:** `aside.filetree` is 240 px wide and full height. It has directory rows (`model/cubes/`, `model/views/`, `model/globals.py`) at 28 px, 12 px, weight 600, `text-secondary`. File rows are 28 px, IBM Plex Mono 12 px; the current file uses `accent-soft` background and `accent` text at weight 600. A file with errors gets a red "●". Under the tree sit "+ New cube" and "+ New view", and the pane head reads "Model" with a "main · dev mode" badge. Choosing a file swaps the editor in place.
- **App:** `/model` is a page of `section.model-file` cards, each 960 px wide on `bg-page`, and the page scrolls to 1,093 px. Opening a file goes to `/model/files/cubes%2Forders.yml`, which has no tree. The only way to another file is the top-bar Model link, then a card. There is no New cube or New view anywhere, and no error marker on a file.
- **Evidence:** screenshots of `/model` (card list) and `/model/files/cubes%2Forders.yml` (no `aside`). The snapshot of the editor page has `main > h1 "cubes/orders.yml"`, one button, the form region and the YAML region, with no navigation list.
- **Severity:** blocker.
- **Class:** STRUCTURE. Direction §7b's accepted layout, "file tree … · Form … · YAML on the right", names the tree, and the Spotfire Information Designer elements tree in references.md §Semantic layer backs it.
- **Direction of fix:** make Model a single workspace: a persistent 240 px file tree beside the editor, with the selected file in the URL. Put New cube and New view in the tree, and put the per-file error dot there. The card summary can remain as an empty-selection state, but not as the only way to navigate.

### F2. The editor frame is a padded page, not full-height panes
- **Prototype:** a grid of `240px | minmax(0,1.15fr) | minmax(380px,1fr)` filling y=48–900 flush, with no outer padding. Each pane has a 44 px `.editor-head`. The form head holds the mono file path (12 px, weight 600), History and Save. The YAML head holds the YAML / Join diagram segmented control and "Edits in either side stay in sync". Panes scroll internally, and the document height is 900.
- **App:** `main` has 16 px padding. An `h1.model-file-page__path` (mono 16 px, weight 700, 32 px tall) sits at y=64, and a separate row holds only the Save button at y=112. The form card (`section.model-form`, 6 px radius, bordered) starts at y=152 and the YAML card at y=190. The document is 1,048 px tall, so the whole page scrolls and the YAML pane and Problems scroll away with it.
- **Evidence:** computed values above. Form tabs sit at y=153 in the app and y=92 in the prototype. The YAML editor is 570 px tall in the app and 658 px in the prototype.
- **Severity:** major.
- **Class:** STRUCTURE.
- **Direction of fix:** drop the page title and the separate Save row. Put the file path and actions in a 44 px pane head as the prototype does, and make the panes flush and full height with their own scrolling.

### F3. Reference fields are free text
- **Prototype:** `schema.js` types these as `refs`, toggle-chip multi-pickers scoped to real members, with "All (*)" for view includes and ordered numbering for hierarchy levels. Single references are `ref` selects, such as the pre-aggregation `time_dimension` and the join "Target cube".
- **App:**
  - Pre-aggregation Measures, Dimensions, Segments and Rollups are text inputs with the placeholder "member, member".
  - Time dimension is a text input holding "ordered_at".
  - The join's target is a text input labelled "Name", not "Target cube".
  - The measure's "Drill members" is a text input.
  - A view cube's Includes is a textarea containing YAML (`- count\n- total_amount…`), and Excludes is a "member, member" input.
- **Evidence:** the `monthly_orders.yml` Pre-aggregations tab and the `secured_orders.yml` Cubes tab (screenshots). The control dump for the Joins tab gives `INPUT:Name, SELECT:Relationship, TEXTAREA:SQL`.
- **Severity:** major.
- **Class:** STRUCTURE. Direction §7b's Rows bullet is explicit ("Reference fields … use member pickers, never free text"), but no AC names pickers. AC-132 and rule 26 cover keys and enums only.
- **Direction of fix:** use the prototype's chip picker for member lists, scoped the way the prototype scopes them. Pre-aggregation measures and dimensions include joined cubes. View includes draw from the join-path cube and offer "All (*)". Hierarchy levels are ordered. Use a select for single references and for join targets.

### F4. Member rows lack badges and SQL previews; expanded rows show every field for every shape
- **Prototype:** `.mrow-head` is at least 34 px, 12 px text, laid out as caret, name with `.mbadge` pills (PK, hidden, format, rolling, multi-stage, sub-query, case), the type right-aligned, and a mono `.sqlp` SQL preview line in `text-muted`. The expanded `.mrow-body` sits on `bg-subtle` with 40 px left indent. Fields come in collapsible uppercase groups (Basics, Formatting, …). A "Defined by" segmented control (SQL expression / CASE / WHEN / Latitude + longitude / Switch values) shows only the fields for that variant, and pre-aggregation fields are filtered by `type` through `show:`. "Remove dimension" sits inside the body in `--err`.
- **App:**
  - The collapsed row is a bordered `details.model-member` (6 px radius) showing only "id number". There is no PK badge, although `primary_key: true` and `public: true` are both set, and no SQL preview.
  - Remove is a separate button outside the row, at x=752.
  - The expanded `id` row is **1,774 px tall** with 33 labelled fields in one ungrouped grid: Case, Switch, When, Else, Latitude, Longitude, Values, Multi stage, Add group by, and more.
  - The pre-aggregation of type rollup shows Rollups, Union with source data, Stream offset and Output column types.
- **Evidence:** the Dimensions-tab screenshot. The field list is from `details.querySelectorAll('label')`.
- **Severity:** major.
- **Class:** STRUCTURE, backed by direction §7b's Rows bullet: "showing name, type, SQL preview, and badges for primary key, public, and format".
- **Direction of fix:** follow the prototype's row anatomy (badges, type on the right, SQL preview) and its body anatomy: grouped collapsible sections, a variant control for dimension shape, and type-dependent visibility for pre-aggregation fields. Move Remove into the body.

### F5. The header has no draft state
- **Prototype:** the form head has History and "Save & reload Cube", and the tree head has a "main · dev mode" badge, which makes clear these edits are a draft on a branch.
- **App:**
  - The only action is "Save & reload Cube", disabled until you edit.
  - An edit (Title → "Orders critique") enables it but shows nothing else: no dirty dot, no "unsaved" text, no Discard.
  - After a reload the Title field is empty again and the YAML no longer has the edit. The draft is gone, with nothing offering to restore it.
  - There is no History.
- **Evidence:** the `main` buttons list after an edit is `["Save & reload Cube","YAML","Join diagram"]`, and there is no `[aria-live]` text. After reload, the non-empty inputs were `["orders","One row per order line…"]`.
- **Severity:** major.
- **Class:** STRUCTURE.
- **Direction of fix:** show that the file has unpublished changes, both in the head and on its tree row. Offer Discard, and keep the draft across navigation or warn before losing it. History comes from the prototype and needs a spec decision first; flag it rather than invent it.

### F6. Problems panel: no warnings count, not docked, no source note
- **Prototype:** `.problems` is fixed at 150 px under the YAML, flush, with a top border. The header tab reads "Problems · n errors · n warnings", with a muted right-hand note naming the validator. Rows are 28 px, 12 px text, laid out as icon, message, and `file:line` in 12 px `text-muted`. Clicking a row jumps to the line and to the matching form tab.
- **App:**
  - `section.model-problems` is a 66 px bordered card (4 px radius) 8 px below the editor.
  - The heading is "Problems · 0 errors" or "· 1 error", with no warnings count in any state I saw.
  - `span.model-problems__where` is **11 px**, under the 12 px floor in direction §3.
  - Clicking a row focuses the code (`activeElement = .cm-content`), which works.
- **Evidence:** computed styles on `.model-problems__where` (font-size 11px, colour #6e6c67) and the heading text in both states.
- **Severity:** minor for the missing warnings count, since direction §7b asks for Errors and Warnings. Minor for the floor breach.
- **Class:** STRUCTURE (errors and warnings, docking) and VISUAL (the 11 px floor).
- **Direction of fix:** dock the panel at a fixed height under the YAML, count warnings, and set the location text to 12 px.

### F7. The local validator does not flag an invalid enum value
- **Prototype:** `validate()` flags, for example, `Measure 'x': type "…" is not valid` and "has no primary_key dimension", before any Cube round-trip.
- **App:** a draft with `type: summ` on a measure left Problems at "0 errors" and enabled Save, so the error would surface only at publish.
- **Evidence:** the draft's Problems text read "Problems · 0 errors / No problems in cubes/orders.yml" (draft since discarded).
- **Severity:** minor. AC-136 puts the authoritative check at publish, and I couldn't observe it (see the coverage gap).
- **Class:** STRUCTURE. The Validation bullet in direction §7b lists validator-style problems linked to line and field.
- **Direction of fix:** run the schema's enum and required-key checks on every parse and list them in Problems with line numbers, before the user tries to publish.

### F8. The parse-error banner sits outside the form pane and shifts the form
- **Prototype:** `.readonly-veil` renders inside `#mform`, below the tabs (y=129), at 13 px in `--err`, and the tabs stay put. The error line in the code is tinted with `rgba(208,59,59,.12)`, and the file's tree row gets a red dot.
- **App:** `p.model-editor__veil[role=status]` renders above the form card at y=152 and pushes the tabs from y=153 to y=209, a 56 px layout shift. The error line has only a gutter dot and an underline, with no line tint and no marker on a file row, since there is no tree.
- **Evidence:** the parse-error screenshot and computed values: veil at y=152, 44 px tall, `rgb(194,54,47)`, 13 px.
- **Severity:** minor.
- **Class:** STRUCTURE.
- **Direction of fix:** put the notice inside the form pane below the tabs, tint the error line, and mark the file in the tree once F1 lands.

### F9. The General tab has neither groups nor switches, and puts short fields full width
- **Prototype:** collapsible "BASICS" and "ADVANCED" groups (12 px, weight 600, uppercase). Short fields sit two per row, including SQL table as a 28 px mono input. Booleans (Public, Calendar cube) are switches, and fields carry hint text such as "Set exactly one of SQL table or SQL" and "Unique across cubes and views".
- **App:**
  - One ungrouped grid.
  - SQL table is a full-width 54 px textarea, and Calendar sits alone on a half-width row.
  - Public, Calendar and Immutable are `(not set) / true / false` selects.
  - There is no hint text.
  - Inputs are 32 px while the selects beside them are 28 px (Description at 32 px next to Public at 28 px), so fields in the same row don't align.
- **Evidence:** computed heights: input 32 px, select 28 px, textarea 54 px. Prototype `input.sm` is 28 px.
- **Severity:** minor.
- **Class:** STRUCTURE for groups, switches and hints. VISUAL for the mismatched heights; direction §7d names 28 px compact controls for inspectors.
- **Direction of fix:** follow the prototype's groups, the rule that "short fields flow two per row" (direction §7b), switches for booleans with an explicit not-set affordance, and one control height of 28 px.

### F10. Type does not follow the tokens
- **Code font:** the app uses `ui-monospace, SFMono-Regular, Menlo` for YAML, paths and SQL fields. Direction §3 and the prototype use **IBM Plex Mono**.
- **YAML metrics:** the app's editor is 12 px with 16.8 px line height; the prototype's is 12.5 px with 19 px.
- **Weight:** both page headings are weight 700 (`/model` h1 at 24 px, the file-path h1 at 16 px mono). Direction §3 allows only 400 and 600.
- **Severity:** minor.
- **Class:** VISUAL.
- **Direction of fix:** load and use the specified code face, and use weight 600 for headings. The file-path heading disappears into the pane head once F2 lands.

### F11. Empty member tabs show only an add button
- **Prototype:** after the rows comes a `.formbar` with "+ segment" and "n total".
- **App:** Segments 0 and Hierarchies 0 show a lone "+ segment" or "+ hierarchy" button in an otherwise empty card, with no sentence. Direction §6 States asks for an illustration, a sentence and a primary action.
- **Severity:** minor.
- **Class:** VISUAL.
- **Direction of fix:** give empty tabs a one-line explanation of what the section is for, with the add action as the primary button.

### F12. Join diagram edge labels have no plate
- **Prototype:** edge labels have a `bg-page` background with 2 px × 4 px padding.
- **App:** "many to one" is drawn straight over the edge line, so the stroke crosses the text.
- **Severity:** minor.
- **Class:** VISUAL.
- **Direction of fix:** give edge labels the background plate.

## 3. What already matches

**Form tabs.** Cube tabs are General, Dimensions, Measures, Joins, Segments, Hierarchies, Pre-aggregations, Access policy. View tabs are General, Cubes, Dimensions, Measures, Folders, Default filters, Access policy. Both follow the §7b tab set and carry per-tab counts in muted text. Tab metrics match the prototype exactly: 12 px, weight 600, 36 px tall, 0 × 10 px padding, `accent` #1f6f86 selected and #5c5b57 unselected.

**Form→YAML sync (rule 27 / AC-133, pass).** Filling Title wrote `title: "Orders critique"` into the YAML in the same render. The app also **keeps comments** through a form edit (lines 19–22 survived), so the prototype's lossy-comment warning isn't owed for comments. AC-134 is satisfied by not losing anything.

**YAML→form sync (rule 27, pass).** A valid YAML edit to `description` reached the form input in **323 ms**, against the 500 ms limit.

**Parse error (rule 28 / AC-135, pass).** An unclosed `[` on line 44 produced "The YAML doesn't parse (line 44). The form is read-only until the code is fixed." Every field was disabled through `fieldset[disabled]` (`input.matches(':disabled') === true`). Problems listed the message with `cubes/orders.yml:44` and a gutter marker.

**Enums (rule 26, spot-checked).** Dimension type offers string, number, boolean, time, geo, switch. Measure type offers count, number, string, boolean, time, sum, avg, min, max, count_distinct, count_distinct_approx. Pre-aggregation type offers rollup, original_sql, rollup_join, rollup_lambda, auto_rollup. Partition granularity offers hour through year. Join relationship also offers the camelCase aliases the validator accepts.

**Pre-aggregation attributes (AC-142, AC-146).** `by_status_month` lists measures, dimensions, time dimension, granularity (month), partition granularity (year), and indexes (`by_status (status)`) with add and remove.

**Join diagram (AC-138).**
- Rounded-rectangle nodes in mono with an "n dims · n measures" subline, and the current cube outlined in `accent`, as in the prototype.
- Directed arrows labelled "many to one".
- A textual list of edges with links.
- An add-join form with Target cube and Relationship selects plus a Condition field.

**Dynamic files (AC-140).** `product_catalog.yml` opens as read-only code with the reason stated: "Jinja template … It opens read-only here: the form edits plain YAML only."

**File listing (AC-131).** Every file's measures, dimensions, joins and pre-aggregations appear on `/model`. The layout is the problem (F1), not the content.

**YAML pane.** It has line numbers, syntax colouring, a `bg-subtle` gutter (#f0efec, the same as the prototype), and the YAML / Join diagram segmented control (12 px, weight 600, 28 px, `accent` on `accent-soft` when pressed, matching the prototype).

**Save button.** It matches the prototype: 24 px, 12 px, weight 600, 6 px radius, `accent` #1f6f86, white text.

**Dark theme (rule 24, pass).**
- Separate dark tokens, not an inversion: surface #1c1c1b, tab text #b4b3ab (8.1:1), labels 8.1:1, keys #4fb3d1 (7.07:1), strings #f0a35c (8.2:1), comments #97958e (5.69:1), tab counts 5.69:1, line numbers 6.83:1 on #2a2a28, problem text 15.22:1.
- The disabled Save is 2.52:1 at opacity 0.5, which WCAG exempts for disabled controls.
