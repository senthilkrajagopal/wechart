# Critique: Data sources, Jobs, Schedules and Security workspaces against the prototype (2026-09-24)

Produced by the `design-critic` agent and saved verbatim, as part of the
prototype-alignment pass the user asked for on 2026-09-24.

**Compared:** the running app at `http://localhost:5400` (`/jobs`, `/security`, `/schedules`, `/data-sources`) and the prototype at `http://127.0.0.1:5500/index.html` (`#jobs`, `#security`, `#schedules`, `#sources`).

**Method:** everything was captured at 1440×900. For each page I took an accessibility snapshot and read computed styles from matching elements in both builds.

**Interactions exercised:**
- Jobs: both tabs, expanding a query row, clicking a pre-aggregation row, and the dark theme.
- Security: editing the context with valid JSON, invalid JSON and `{}`; the dashboard search with a match and with no match; opening a dashboard preview and its banner.

**Not done, per the demo rules:** no Build, no save, no delete. Where a state could only be reached by one of those, I say so and cite the source file.

**Route note:** the app's Data sources route is `/data-sources`. `/sources` returns "Not found" (finding 22).

## 1. Summary

1. **None of the admin pages has the prototype's list-plus-inspector layout.**
   - The prototype puts a table in `.admin-main` (1040 px wide) next to a docked 400 px right pane that runs the full height, with a left border. Selecting a row fills that pane with detail and actions.
   - Jobs has no right pane at all, and clicking a row does nothing.
   - Security's pane is a floating 320 px card that is only as tall as its content.
2. **Schedules and Data sources are blank.**
   - `<main>` is empty: no title, no note, nothing that says the content is deferred. The page reads as broken rather than as deferred by scope.
3. **The page frame uses browser defaults instead of the prototype's tokens.**
   - The `h1` is the user-agent default: 28 px, weight 700, with an inherited 20 px line-height. The prototype's is 20/26 at weight 600.
   - Page padding is 16 px on all sides; the prototype uses 16 px top and bottom and 24 px left and right.
   - Tables sit bare on the page wallpaper: no card, no header band, 14 px cells, rows 37–41 px tall, and no tabular numerals.
4. **The Jobs pre-aggregation list is thin.**
   - Its columns are only Pre-aggregation, Type, Partitions and Build. There is no status, no trigger and no link to the model (Checklist 22), and no row selection.
   - Build progress appears in a separate "Builds" list under the table instead of in the row and a detail pane.
5. **The Queries log is one very long table.**
   - 87 rows render into a 3,549 px page, with no filters, no sorting and no sticky header.

## 2. Findings

### Jobs

**1. There is no job detail pane.**
- **Prototype:** clicking a pre-aggregation row highlights it (`tr.sel`, `accent-soft`) and fills `aside.pane.right`. That pane is 400 px wide, 852 px tall and starts at x=1040. It has a 44 px `pane-head` showing the id, then the status and trigger, then Build all, Build selected and Open in Model, then a Partitions table and a build-duration chart.
- **App:** `document.querySelectorAll('aside').length === 0`. A row has `cursor: auto`, and clicking the name cell changes nothing.
- **Evidence:** screenshots of both at `/jobs`; snapshot uid 20_28 was clicked with no result.
- **Severity:** major
- **Class:** STRUCTURE (the Partitions section in that pane is DEFERRED, see finding 25)
- **Fix direction:** adopt the admin grid (fluid main column plus a 400 px docked pane) as a shared layout. Make pre-aggregation rows selectable. Put the selected rollup's state, trigger, Build and "Open in Model" in the pane.

**2. The pre-aggregation list is missing Checklist 22's columns.**
- **Prototype columns:** Pre-aggregation, Status (icon and label), Last success, Duration vs avg, Trigger, Partitions, Source.
- **App columns:** Pre-aggregation, Type, Partitions, and an unlabelled Build column. Rows show no state at all and no model link.
- **Evidence:** the `thead` of `table.query-log[aria-label="Pre-aggregations"]`, and `packages/web/src/workspaces/jobs/BuildPanel.tsx:163-198`.
- **Severity:** major
- **Class:**
  - STRUCTURE: Checklist 22's status, trigger and model link. The trigger is the rollup's `refresh_key` from the model; the state is whatever Cube's jobs API last reported this session, or "Not built here".
  - DEFERRED: last success and duration-vs-average, which need wechart's own build history (AC-150).
- **Fix direction:**
  - Add a Status column that uses the existing `.status` icon-and-label.
  - Add a Trigger column read from `refresh_key`.
  - Link each name to its definition in Model.
  - Leave the two history columns out until AC-150 returns, rather than showing them empty.

**3. Build progress is reported away from the row it belongs to.**
- **Prototype:** a build changes the row's own Status cell (Scheduled, then Processing, then Done) and the pane.
- **App (from source; not triggered, per the demo rules):** a separate "Builds" `h2` and list is added below the table, with one entry per started build showing tokens and a `StateBadge`. The row itself never changes.
- **Evidence:** `BuildPanel.tsx:203-217`.
- **Severity:** minor
- **Class:** STRUCTURE
- **Fix direction:** show the latest build state in the row's Status cell. Move the per-token list into the detail pane, under the selected rollup.

**4. The "Partitions" column holds a granularity, not partitions.**
- **Prototype:** the column shows a partition count, right-aligned with tabular numerals.
- **App:** it shows `year`, the partition granularity, under the header "Partitions".
- **Severity:** minor
- **Class:** STRUCTURE
- **Fix direction:** rename the column "Partition granularity", or show the count when Cube exposes one.

**5. The Queries log has no filters, sorting, sticky header or paging.**
- **Prototype:** the log-like tab (Run history) has a filter row of three `select.sm` controls (status, trigger, time range). Its `th` is `position: sticky` inside a scrolling `.admin-main`, so the page frame stays put.
- **App:**
  - 87 rows render at once, and the document is 3,549 px tall.
  - The `th` is `position: static`: after scrolling 1,500 px the header row sits at y = −1,309, off screen.
  - There are no controls at all (`panel.querySelectorAll('select,input,button').length === 0`) and no sort.
  - The whole document scrolls. The top bar is sticky, but the title and tabs scroll away.
- **Severity:** major
- **Class:** STRUCTURE (direction §8: DataGrid "sortable, filterable, virtualized")
- **Fix direction:**
  - Make the admin main column the scroll container, with a sticky table header.
  - Add filters for outcome, source (live or pre-aggregation) and time range.
  - Page or virtualize the rows.

**6. The Queries caption is placed and styled differently.**
- **Prototype:** explanatory notes are `p.xs.muted` (12/16, `#76746f`) placed below the table.
- **App:** a centred `<caption>` at 14/20 in the primary text colour, above the header row.
- **Severity:** minor
- **Class:** VISUAL
- **Fix direction:** left-align it at 12 px muted, or turn it into a note below the table.

**7. In the Outcome column, the status icon sits high and cells are top-aligned.**
- **Prototype:** `.status` uses `align-items: center`, and cells are middle-aligned.
- **App:** `.query-log__outcome .status` uses `align-items: flex-start`, and every `td` has `vertical-align: top`. The check icon sits visibly above the centre of the "Succeeded" label in every row (visible in the screenshot).
- **Evidence:** `styles.ts:767`.
- **Severity:** minor
- **Class:** VISUAL
- **Fix direction:** centre the icon against a single-line label. Keep top alignment only for rows that expand (the query details).

**8. The header's health indicators are bare text, not pill badges.**
- **Prototype:** the header row holds the `h1` and pill `.badge`s (22 px tall, `bg-subtle #f0efec`, 999 px radius, 12 px). The refresh-worker badge is pushed to the right.
- **App:** `.jobs-health` holds bare `.status` spans ("Cube healthy", "Refresh worker not watched") right after the title, with no background.
- **Severity:** minor
- **Class:** VISUAL
- **Fix direction:** render health as badges, and right-align the refresh-worker state as the prototype does.

### Frame shared by Jobs and Security

**9. The page title is the browser-default `h1`.**
- **Prototype:** `.admin-main h1` is 20 px, line-height 26 px, weight 600 (direction §3 `text-lg`, page titles).
- **App:** the `h1` on `/jobs` and on `/security` is 28 px, weight 700, line-height 20 px. Its box is 20 px tall, so the glyphs overflow it.
- **Evidence:** computed styles.
- **Severity:** major (it is the most prominent element on every admin page, and weight 700 is outside §3's 400/600)
- **Class:** VISUAL
- **Fix direction:** give workspace page titles the `text-lg` token.

**10. Page padding and title position differ.**
- **Prototype:** `.admin-main` padding is 16 px top and bottom, 24 px left and right. The title sits at x=24, y=65.
- **App:** `main` padding is 16 px on all sides. The title sits at x=16, y=83.
- **Severity:** minor
- **Class:** VISUAL
- **Fix direction:** use the prototype's 16/24 padding for admin pages, matching the 24 px side inset already adopted for dashboards (direction §7d).

**11. Admin tables are not the prototype's grid table.**

| Aspect | Prototype | App |
| --- | --- | --- |
| Container | `.card`: `#fff` background, 1 px `#e3e2de` border, 6 px radius | Bare on `bg-page #f4f4f2`: transparent background, no border |
| Header row | 28 px tall, `bg-subtle #f0efec`, text-primary `#1f1f1e` | 36.5–37 px tall, no background, text-secondary `#5c5b57` |
| Body rows | 34 px (`comfy`), 12 px text | 41 px (pre-aggregations), 38 px (queries), 37 px (policies), 14 px text |
| Numerals | tabular | `font-variant-numeric: normal`, including the Duration and When cells |

- **Severity:** major. Tabular figures are Checklist 1 ("Tables … use tabular numerals"); the remaining rows of the table are tokens.
- **Class:** VISUAL
- **Fix direction:** one shared admin table component: a card wrapper, a header band in `bg-subtle`, 34 px rows (24 px for the dense log), 12 px cells, and `tnum`.

### Security

**12. The context preview is a floating card, not a docked pane.**
- **Prototype:** `aside.pane.right`, 400 px wide and 852 px tall at x=1040, with a left border. A 44 px `pane-head` with a bottom rule holds "Preview a security context", followed by `.section` blocks that each have a 12 px uppercase `h3`.
- **App:** `section.context-preview` is 320 × 329 px at x=1104, y=64: a 16 px inset from the edge, a 1 px border all round, 6 px radius, 12 px padding. The `h2` sits inside the card, not in a header band.
- **Severity:** major
- **Class:** STRUCTURE
- **Fix direction:** use the same docked admin pane as Jobs (finding 1).

**13. The "Effective access" section and the context presets are missing.**
- **Prototype:**
  - Under the JWT textarea there are preset buttons: EU rep, Americas rep, Admin, No groups.
  - An "Effective access" section lists every cube with a level label (Full, Rows filtered, No access, Open) and a one-line reason.
  - A primary "Preview dashboard with this context" button follows.
- **App:** a textarea, helper text naming the groups the policies use, and a "Find a dashboard" search box. The policy outcome for a context is only visible after opening a dashboard. The generated SQL does appear per tile in the preview (`DashboardView.tsx:2451`), so AC-168 itself holds.
- **Severity:** major
- **Class:** STRUCTURE
- **Fix direction:**
  - Compute and list each cube or view's access under the current context, with a label and an icon, never colour alone.
  - Offer a preset per group that the policies name (the app already lists them: managers, sales, auditors, finance).

**14. Dashboard results are raw browser links, with no limit and no empty state.**
- **Prototype:** one primary button.
- **App:**
  - Typing "a" lists 43 links. Each is `rgb(0, 0, 238)`, underlined, 14 px and 16.5 px tall: the user-agent default link style, not the `accent #1f6f86` token.
  - The card grows to 1,368 px, which makes the page 1,448 px tall.
  - A query with no match ("zzzzqq") shows nothing at all, not even a "No dashboard matches" line.
- **Severity:** major
- **Class:** VISUAL (the link colour is off-token) and STRUCTURE (unbounded list, missing empty state)
- **Fix direction:**
  - Use a styled, bounded result list (28 px rows, accent colour, scrolling after about 8 rows) or a combobox.
  - Add an explicit no-match message.
  - Keep one clear primary action to start the preview.

**15. There is no way from a policy to the model.**
- **Prototype:** an "Edit policies in Model" button (a 32 px `.btn`) sits in the page header.
- **App:** there is no header action, and the Source cells (`views/secured_orders.yml`) are plain text, not links (snapshot uids 22_35, 22_42, 22_49 are StaticText).
- **Severity:** major (direction principle 1, "One object, many views")
- **Class:** STRUCTURE
- **Fix direction:** add the header action, and make each Source cell open that file in Model.

**16. The phase-2 note is a plain paragraph.**
- **Prototype:** a `.warnbar` with an info icon, `accent-soft` background, a 1 px border and a 6 px radius.
- **App:** `p.security-workspace__note`, 14 px text-secondary, with no container and no icon.
- **Severity:** minor
- **Class:** VISUAL
- **Fix direction:** use the info bar used across the prototype's admin pages (the same one appears on the prototype's Data sources page).

**17. Cubes with no policy are presented as a warning.**
- **Prototype:** the last row of the policies table reads "No access_policy. Open to every security context." in neutral secondary text. In Effective access, "Open" gets a neutral grey swatch.
- **App:** a separate line outside the table with the warning triangle icon ("No access_policy, so open to every security context: …").
- **Severity:** minor
- **Class:** STRUCTURE
- **Fix direction:** keep it as a table row in neutral styling. Reserve the warning icon for real problems, such as the "Not read here … (Jinja)" note, which rightly keeps it.

**18. The edited context is lost after a preview.**
- **Prototype:** the security context is kept while moving between surfaces.
- **App:** after previewing a dashboard and coming back to `/security`, the textarea has reset to `{}`.
- **Severity:** minor
- **Class:** STRUCTURE
- **Fix direction:** keep the last context for the session, or restore it from the preview URL on return.

**19. The preview banner's text colour differs.**
- **Prototype:** `.viewas` uses `crossfilter-soft` as the background and `crossfilter` purple as the text colour.
- **App:** `.preview-banner` has a lavender background and a purple 1 px bottom border, but the text is text-primary `#1f1f1e`, 13 px, weight 600.
- **Severity:** minor
- **Class:** VISUAL
- **Fix direction:** match the prototype's text colour, or record the difference in direction §7d.

### Schedules and Data sources

**20. Schedules renders an empty page.**
- **Prototype:** an `h1` "Schedules", a note explaining the two schedulers, the schedule table, and a detail pane.
- **App:** `<main></main>` is empty (screenshot: blank below the top bar). No requests are made and nothing is logged to the console. `routes.tsx:61-74` has no entry for `schedules`.
- **Severity:** major
- **Class:**
  - STRUCTURE: the frame.
  - DEFERRED: wechart-owned schedules, the cron editor, next runs and suspend/Resume (AC-153, AC-154, AC-155).
- **Fix direction:** render the page frame (title and an info bar saying wechart's scheduler is deferred). If Cube-owned `refresh_key` schedules are to appear, list them read-only, labelled "Cube refresh worker", with "Edit in Model" as the only action.

**21. Data sources renders an empty page.**
- **Prototype:** an `h1`, "+ Data source", an info bar about `driverFactory`, the sources table, and a detail pane with General, Connection, Advanced, Test and Usage tabs.
- **App:** `<main></main>` is empty. The switcher marks the tab `aria-current="page"` over a blank page.
- **Severity:** major
- **Class:** STRUCTURE for the frame; DEFERRED for the content (AC-157 … AC-161, AC-163, AC-164)
- **Fix direction:** show the title and a note saying connection management is deferred. Point to Model, where `data_source` is assigned (AC-162).

**22. `/sources` returns "Not found" and highlights Explore.**
- **App:** `http://localhost:5400/sources` renders `h1` "Not found" with the Explore tab marked as current.
- **Severity:** minor
- **Class:** STRUCTURE
- **Fix direction:** redirect `/sources` to `/data-sources`. On not-found pages, mark no workspace as current.

### States

**23. Loading and error states in Jobs are single text lines.**
- **Prototype and direction §6 / Checklist 18:** an error offers Retry and a Details disclosure.
- **App (from source; not reachable without breaking the demo):**
  - Loading is `StateLine kind="run"` ("Reading the query log…").
  - An error is `StateLine kind="err"` with the message only: no Retry, no Details (`JobsPage.tsx:32-33`, `BuildPanel.tsx:149-156`).
  - An empty model gives a bare `<p>`: "The model declares no pre-aggregations."
- **Severity:** minor (unverified in the browser)
- **Class:** STRUCTURE
- **Fix direction:** use the shared error pattern (icon, message, Retry, Details), and an empty state with a sentence and an "Open in Model" action.

## 3. What already matches

1. **Jobs tabs match the prototype exactly.**
   - Both are 36 px tall, 12 px weight 600, with 0 × 10 px padding.
   - The selected tab is `rgb(31,111,134)` with a 2 px accent underline; unselected tabs are `#5c5b57`.
   - The white tab band is 37 px tall with a bottom rule.
   - The tablist follows the ARIA tabs pattern (`role=tablist`, `aria-selected`, roving `tabIndex`, arrow keys) in `JobsPage.tsx:54-83`.
2. **The status primitive matches the prototype's `.status` (Checklist 3, AC-152, AC-177).**
   - Both use `inline-flex`, a 6 px gap, 12 px weight 600, and the same SVG icons.
   - Success is `#1d7a3f`, warning `#8a5a00`, error in the error token.
   - Every state seen pairs an icon with a word: "Cube healthy", "Refresh worker not watched", "Succeeded", "Granted", "Not JSON: Unexpected end of JSON input".
3. **The small button matches `.btn.sm`.** "Build" is 24 px tall, 12 px, 0 × 8 px padding, 6 px radius, 1 px `#c9c7c1` border, on `#fff`.
4. **Type floor (Checklist 1, 12 px floor).** A walk over the text nodes in Jobs `main` found 12 px ×96, 14 px ×523 and 28 px ×1, and nothing below 12 px. Security's text is likewise 12 px or larger.
5. **Contrast (Checklist 2).** Table headers `#5c5b57` on `#f4f4f2` give 5.91:1, and the status tokens are at or above 4.67:1, as in direction §5's table. No new colours were found apart from the user-agent link blue in finding 14, which is 9.4:1 on white: it passes contrast but is off-token.
6. **Dark theme (Checklist 24).** The Jobs Queries tab in dark mode shows the whole frame, table, badges and status colours re-tokenised. It is not an inversion: the success and warning hues are lightened per §5.
7. **Security-context preview banner (Checklist 21, AC-166).** Choosing a dashboard opens `/explore/dashboards/…?preview=…` with a sticky `.preview-banner` (33.5 px, `position: sticky`). It reads "Previewing as {…}. This dashboard's queries run with this security context." and offers an "Exit preview" link.
8. **Access policies (AC-165).** The table goes beyond the prototype: it has Conditions and Masked columns, and a note naming a model file it could not read (Jinja). The column order Cube/view, Group, Members, Rows, then Source matches the prototype.
9. **Unauthenticated-access warning (AC-169).** A persistent status line reads "Cube refuses requests without a valid token.", with the success icon.
10. **API scopes (AC-170).** A table lists each scope with Granted (icon and label) and what needs it.
11. **Context JSON error state.** Invalid JSON swaps the helper text for an error icon and "Not JSON: …", and hides the dashboard results. The prototype has the same behaviour (`SEC.err`).
12. **Query log content (AC-016).** Each row carries time, the Cube request (expandable to JSON), duration, source ("● Live", an icon and a label) and outcome.
13. **Cube health (AC-156).** The deployment's health and the refresh worker's state appear in the Jobs header, as in the prototype's header badges.
14. **Textarea styling.** The context textarea uses the mono font, 12 px, a 1 px `#c9c7c1` border and a 4 px radius, matching the prototype's `.input` rule for inputs.
