# Decisions: the Text tile, dashboard parameters and AI summaries (lane TEXT)

Later decisions for P2.26 (F45–F48, designs 21 and 22), in the table of [`decisions-2026-10-08.md`](./decisions-2026-10-08.md)'s "Later decisions", kept here so the parallel lanes don't conflict there.

| ID | Question | Decision | Why | Departs |
|---|---|---|---|---|
| T868-1 the stored document's shape (AC-513, AC-518; research §1, Storage) | What is stored, under which names, and where do controls sit? | **`{ version: 1, doc }`, `doc` being ProseMirror's JSON under Tiptap's own node and mark names where StarterKit has one: `doc`, `paragraph`, `heading` (`level` 1, 2 or 3: Heading large, medium, small, as `#`, `##` and `###` type them, AC-516), `bulletList`, `orderedList` (`start`), `listItem` (paragraphs and lists), `text`, `hardBreak`; marks `bold`, `italic` and `link` (`href` only). Large value is a block of its own, `largeValue`. Every element is an inline atom, controls and buttons too: `value`, `change`, `sparkline`, `icon`, `bulletGraph`, `marking`, `filterValue`, `asOf`, `filterControl`, `parameterControl`, `actionButton`. An element may be bold or italic, never a link.** Each element stores only what names its source and its settings (design 21 C1–C6, E): a member as `cube.member`, a marking by name (as tokens do), a dashboard filter, parameter, page, bookmark or tile by id; live elements take an optional own filter (`filters`, a chart filter's shape, AC-216) and `marking`. Only the source is required, so an element inserted from the menu is valid before its settings are chosen. A Change's `compare` holds only `previous_period` until R80-1 is answered. Lane TEXT's call, overturnable. | Tiptap's names let the editor read and write the stored tree with no mapping; wechart's version and check make it wechart's shape (research §1). Inline controls let a sentence hold a control and let them stack below 1,024 px (state K) without a second content model. | No |
| T868-2 what "a wechart dashboard" link is (AC-513, rule 42) | A link must go to an http(s) address or a wechart dashboard. In what form? | **An absolute `http://` or `https://` address with a host and no whitespace or control character, or the path `/explore/dashboards/‹id›`, optionally with a query or fragment, as the Link/button tile builds it (AC-064).** `http:host` without slashes, `//host`, any other wechart path and every other scheme are refused, named "The link "‹href›" isn't an http(s) address or a wechart dashboard." Lane TEXT's call, overturnable. | `http:evil.example` parses as a URL but, as an href, resolves against wechart's page (LinkTile's own note). A pattern rather than `URL`, since core has no DOM library. | No |
| T868-3 how strict the check is (AC-513) | Tiptap's `getJSON()` writes every attribute an extension declares, defaults included (`orderedList.type`, `link.target`, `rel`, `class`). Does the schema accept those? | **No. The check refuses any node, mark, attribute or field it doesn't declare, a text node's `attrs` included; the editor's output is brought to this schema (only declared attributes) before it's saved, in the editor's own tasks (T876, T880).** The document is walked with a stack, not by recursion, so no depth of nesting overflows. Every problem is named, not just the first. Lane TEXT's call, overturnable. | Research Gotchas: the static renderers check neither links nor stray attributes, so the stored tree must hold only what we declare. A 400 that names every problem lets an MCP client fix a document in one round. | No |
