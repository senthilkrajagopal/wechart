# Decisions: the Text tile, dashboard parameters and AI summaries (lane TEXT)

Later decisions for P2.26 (F45–F48, designs 21 and 22), in the table of [`decisions-2026-10-08.md`](./decisions-2026-10-08.md)'s "Later decisions", kept here so the parallel lanes don't conflict there.

| ID | Question | Decision | Why | Departs |
|---|---|---|---|---|
| T868-1 the stored document's shape (AC-513, AC-518; research §1, Storage) | What is stored, under which names, and where do controls sit? | **`{ version: 1, doc }`, `doc` being ProseMirror's JSON under Tiptap's own node and mark names where StarterKit has one: `doc`, `paragraph`, `heading` (`level` 1, 2 or 3: Heading large, medium, small, as `#`, `##` and `###` type them, AC-516), `bulletList`, `orderedList` (`start`), `listItem` (paragraphs and lists), `text`, `hardBreak`; marks `bold`, `italic` and `link` (`href` only). Large value is a block of its own, `largeValue`. Every element is an inline atom, controls and buttons too: `value`, `change`, `sparkline`, `icon`, `bulletGraph`, `marking`, `filterValue`, `asOf`, `filterControl`, `parameterControl`, `actionButton`. An element may be bold or italic, never a link.** Each element stores only what names its source and its settings (design 21 C1–C6, E): a member as `cube.member`, a marking by name (as tokens do), a dashboard filter, parameter, page, bookmark or tile by id; live elements take an optional own filter (`filters`, a chart filter's shape, AC-216) and `marking`. Only the source is required, so an element inserted from the menu is valid before its settings are chosen. A Change's `compare` holds only `previous_period` until R80-1 is answered. Lane TEXT's call, overturnable. | Tiptap's names let the editor read and write the stored tree with no mapping; wechart's version and check make it wechart's shape (research §1). Inline controls let a sentence hold a control and let them stack below 1,024 px (state K) without a second content model. | No |
| T868-2 what "a wechart dashboard" link is (AC-513, rule 42) | A link must go to an http(s) address or a wechart dashboard. In what form? | **An absolute `http://` or `https://` address with a host and no whitespace or control character, or the path `/explore/dashboards/‹id›`, optionally with a query or fragment, as the Link/button tile builds it (AC-064).** `http:host` without slashes, `//host`, any other wechart path and every other scheme are refused, named "The link "‹href›" isn't an http(s) address or a wechart dashboard." Lane TEXT's call, overturnable. | `http:evil.example` parses as a URL but, as an href, resolves against wechart's page (LinkTile's own note). A pattern rather than `URL`, since core has no DOM library. | No |
| T869-1 reading the markdown subset into a document (AC-512) | The markdown tile drew six heading depths, code spans and no links. The Text tile has three headings, no code mark and links. How does each read? | **`#`, `##` and `###` are Heading large, medium and small, as AC-516 types them; `####` and deeper are Heading small. A code span is its literal text, backticks included, with any braces in it left as text. `[text](address)` is a link where the address passes T868-2 and holds no brace; where it doesn't pass, the brackets and address are text and the words read as the tile drew them, emphasis and tokens too; a token in an address is a live value, as the tile drew it. A token keeps the emphasis around it and its place, and is never inside a link: a link's words either side of it stay linked. A numbered item counts from its own number, from 0, up to nine digits; a longer number is a paragraph's text. A markdown tile's backslashes are text, as it drew them. Only when asked (`escapes`, for markdown T870 wrote and an MCP client sends back, AC-527) is a backslash before ASCII punctuation that character as text (`\*`, `\{{`, `\#`). Noncharacters U+FDD0…U+FDEF in any text read as U+FFFD.** Lane TEXT's call, overturnable. | AC-512: headings, emphasis, lists, line breaks and links read as AC-208 renders them, and "anything else … as the literal text it was"; a code span is in neither list. A heading's size by its marks matches what an author types (AC-516). The schema keeps a list's start a safe whole number. The escapes' stand-ins are noncharacters, so no typed character is mistaken for one (T869's review). | Yes: `####`+ headings and code spans look different from before; and a tile's lone `##` heading, drawn as h3 by rank before, is h4 once T873 draws levels 1–3 as h3–h5 |
| T870-1 the markdown form of a Text document (AC-527) | Which token names each element, what has no markdown form, and how does typed text survive? | **Value and Marking keep the markdown tile's tokens (`{{measure:m}}`, `{{measure:m \| marking:‹name›}}`, `{{marking:‹name›.count}}`/`.summary`). The others are `{{change:m \| vs:previous_period}}`, `{{sparkline:m}}`, `{{icon:m}}`, `{{bullet-graph:m}}`, `{{as-of:m}}`, `{{filter-value:‹filter id›}}`, `{{filter-control:‹filter id›}}`, `{{parameter-control:‹parameter id›}}` and `{{button:‹label›}}`; their other settings have no markdown form, and T869 reads these tokens back as text. Bold is `**`, italic `*`, nesting bold outside italic outside a link, with a run's edge spaces outside its markers. A Large value is written as a paragraph. A nested list or a list item's later blocks are indented two spaces, which T869 reads as text. Typed `\`, `*`, a backtick, brackets, the first brace of `{{`, an underscore outside a word, and a heading or list start are escaped with a backslash, which T869 reads back with `escapes` (T869-1). A link's parentheses are percent-encoded.** Lane TEXT's call, overturnable. | The task's tokens, and the markdown kinds' text and elements read back the same (AC-527). Ids, not names, because core holds only the document; T891 may name them for MCP. | No |
| T868-3 how strict the check is (AC-513) | Tiptap's `getJSON()` writes every attribute an extension declares, defaults included (`orderedList.type`, `link.target`, `rel`, `class`). Does the schema accept those? | **No. The check refuses any node, mark, attribute or field it doesn't declare, a text node's `attrs` included; the editor's output is brought to this schema (only declared attributes) before it's saved, in the editor's own tasks (T876, T880).** The document is walked with a stack, not by recursion, so no depth of nesting overflows. After T868's review: names every object inherits (`constructor`, `__proto__`, `toString`) are refused by name, not looked up; a line break may carry bold, italic or a link, as ProseMirror marks every inline node in a selection; a list holds at least one item and a list item starts with a paragraph, as StarterKit's lists do, so a document that passes opens in the editor. Every problem is named, not just the first. Lane TEXT's call, overturnable. | Research Gotchas: the static renderers check neither links nor stray attributes, so the stored tree must hold only what we declare. A 400 that names every problem lets an MCP client fix a document in one round. | No |
