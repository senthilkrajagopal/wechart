# Phase 2: security, AD-group folders and user workspaces (the user, 2026-09-25)

Raw input, verbatim, from the conversation that opened phase 2. Like everything in `docs/inputs/`, it feeds the interview. It isn't itself a requirement, and any claims it makes about third-party behaviour must be checked by research.

> oksy for phase 2.. these are the main things we will be doing... first of all implement security. Security will be using oidc/sso... so i guess the best strategy is to use the oauth2-proxy/oidc.. it will be configurable. if it is not enabled.. it will work in single user mode. the other requirement is that the access to folders will be enabled through AD groups. Folders may have one or more AD groups assigned to it. If no AD group is assigned it will inherit from parent. If AD group is assigned to any folder in the tree then the user belonging to that group will be able to see everything in the same parent path going back to the root.. and the user will be able to see all children for that folder (even if a child AD group overrides that permission). There will be three roles.. Super-Admin, Admin and User. Super-Admin is an AD group member of the AD group will have super admin permissions, which is access to all admin features. Admin has permissions to create new datasources, models, dashboard, charts within that specific folder. User has view only permissions to the dashboards in that folder and along the parent path that we discussed earlier. As part of phase 2.. lets remove the model tab.. and include the models into the folder view. The admins/users will be able to access and use any datasource in the parent path.. and all children. let us also move datasources in the folders with the same access restrictions. Hope it make sense... I can clarify more during the interview.  When users work on creating or editing dashboards/charts/models/datasources. it will always be done from users workspace. The users workspace is accessible only to that specific user. Sharing can happen only from users workspace.. the AD group based folder will support only AD groups and will not support individual user assignment. From a users workspace, he will be able use datasource/models/dashboards/charts from the main folders based on the access restrictions. After editing the user will have the option to copy the changes (dashboard/models/datasources) into the main folders.. And similarly while they are starting their work.. they have the option of copying the dashboard/model/datasources into their own workspace and do the change. If they are only making changes to a dashboard, they can copy the dashboard only. We earlier mentioned that cubes cannot have duplicate names... we are relaxing that.. cubes/models/dashboards/datasources cannot have duplicate names within the same folder. Let us say parent and child folder have the same cube called sales, then the resolution of which cube to use will be bottom up starting from current. Let me know if these requirements make sense... .
